## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user song folders / zips -> Image decoder | album.png/jpg are untrusted files from the internet |
| zip archive -> extraction cache | new png/jpg entries written to disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.2-32 | Denial of service | oversized / decompression-bomb image | mitigate | 8 MB file cap before decode, reject > 4096 px after decode, decode on WorkerThreadPool, LRU 32, selected song only, never during scans |
| T-02.2-33 | Tampering | malformed PNG/JPG targeting the decoder | mitigate | Godot built-in decoders only via Image.load_from_file; failure -> generated cover silently; never ResourceLoader on user files |
| T-02.2-34 | Tampering | path traversal via art lookup | mitigate | lookup limited to album.png/album.jpg in chart_path.get_base_dir(); no ini-provided art path honoured |
| T-02.2-35 | Tampering | zip path traversal for image entries | mitigate | existing ZipExtractor.safe_rel checks apply; only extensions added; 8 MB per image entry |
| T-02.2-36 | Information disclosure | third-party album art committed as a fixture | mitigate | fixture generated by the executor; the user's Slipknot album.png is never copied into the repo |
</threat_model>
