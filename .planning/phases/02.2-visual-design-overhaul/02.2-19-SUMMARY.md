# Phase 02.2 Plan 19: Song Select in the design system, with sections Summary

Song Select now sits on the animated `AbyssBackdrop` (table variant). Rows are chamfered glass, and the selected row uses the focus style with a marker bar and caret. Sort, run badges and row badges are `info` / `mode` chips, and the footer and Start Dive use the UiKit button styles. The detail panel is a glass panel with brackets and a new SECTIONS block: a count chip, a strip with a tick per section and the joined names. Sections are parsed lazily on a worker for the selected song only. No colour literal is left in song_select.gd.

## What was built

### Task 1 (TDD: 71af6c9 test, dbf5c11 feat)
- **Background:** an `AbyssBackdrop` with variant "table", named "Backdrop", as the first child. It replaces `Arena(menu_mode)`.
- **Rows** (UI-SPEC 6):
  - Idle: `ABYSS_700` 60% with a 2 px `SONAR` 30% edge and a `CUT_SM` chamfer. Hover raises the edge to 60%.
  - Selected: `ABYSS_600` 92% with a `SONAR` edge, a stroke glow (Full only), a 4 px marker bar at x+8, a 12x16 caret 12 px outside the edge, and a bold title.
  - Broken: "!" in `WARNING_RED`, title `TEXT_LO`. Needs-a-chart: an `info` chip. TEST: a `mode` chip.
- **Header:** "SELECT SONG" in Oxanium Heading. PRACTICE DIVE / AUTOPLAY show as `mode` chips and SORT as an `info` chip. The filter field is a chamfered glass field whose edge turns full `SONAR` while you type.
- **Buttons:** the footer buttons use the 48 px compact style (idle, hover and disabled states) with centred labels. Start Dive uses the primary style, or disabled when the song cannot be played.
- **Sections block:**
  - "SECTIONS" caption at baseline 688, with an `info` count chip once parsed.
  - Strip at 1080..1832 × 700..708 (`ABYSS_500` 60%), with a 2 px `TEXT_LO` tick at each section start (time / song length, clamped).
  - Names at baseline 736 in `TEXT_MID`, joined with ", " and cut with "..." at 752 px. With no sections it shows "No section markers in this chart." in `TEXT_LO`.
  - Broken and needs-a-chart songs keep their reason block and get no sections.
- **Lazy parse (T-02.2-50):**
  - Only the selected playable song is parsed, through `section_loader` (default `parse_sections`) on the WorkerThreadPool.
  - A result is kept only when its request id, song id and "loading" state all match the current selection.
  - Results are cached per song id (64 max). The cache is cleared when a rescan starts.
  - Tasks are reaped in `_process` and `_exit_tree`, the same way as the preview loads.
- **Sweep:** `apply_effect_settings` sets `_sweep = not (low or reduce)`. The rotating sweep and the selection ping are drawn only when it is on. The static rings and crosshair always show.
- **Literals:** every `C_*` constant and the raw `Color(...)` values were replaced with Palette tokens. The legacy aliases ACCENT, TEXT and DESTRUCTIVE are no longer used here. song_select.gd was removed from `PENDING_MIGRATION`.
- **Tests:** 9 new cases in tests/test_song_select.gd (52 total):
  - the backdrop replaces the Arena
  - sweep on in Full, off in Low and in Reduce motion
  - row colours
  - section geometry and tick x
  - `parse_sections` on the community fixture chart (Intro, Verse 1, Chorus), plus broken, missing and null entries giving []
  - names text joining, truncation and the empty line
  - lazy load with the per-id cache (the loader runs once per song)
  - no parse for unplayable songs
  - a stale result is dropped
- SongListModel, scan, filter and sort code are untouched.

Fixed after the first review (scenario re-run afterwards):
- The row length text ("0:02") touched the first difficulty pip. It is now right-aligned at x 892 (12 px gap).
- The badge chips (TEST, NEEDS A CHART) sat 8 px from the title. The gap is now 12 px, and the harness and painter share the constant.

Accepted as-is, with reasons:
- In the art shot, the Chorus and Outro ticks overlap at the strip's right end. The fixture song is 2 s long and those sections sit at 2 s and 3 s, so they clamp to the end. Real songs (HRT) spread their ticks correctly.
- The fixture album.png is the plan-17 64x48 two-tone test image, so the "art" is two flat halves. That image is correct for a fixture.
- On broken / needs-a-chart songs the area between the reason block and the visualizer line (about y 600..760) is empty. The reason block layout comes from 02-UI-SPEC, and there are no sections to show for those songs.
- With no song at all (empty library), the detail panel shows "-" stats and dimmed tiles over the sonar rings. This empty-panel behaviour is unchanged from 02, and the list side carries the message on a glass panel.
- The silent visualizer bands draw as a dashed 2 px baseline. This was accepted in plan 18.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Focus caret would be clipped by the list pane**
- **Found during:** Task 1
- **Issue:** The UI-SPEC focus caret sits 12 px outside the row's left edge (x 40..52). The list pane started at x 64 with `clip_contents`.
- **Fix:** The pane now starts at x 32 (width 1008). Rows and hit-testing are unchanged.
- **Commit:** dbf5c11

**2. [Rule 3 - Blocking] The harness rows-fit check measured the old outline-badge width**
- **Found during:** Task 2
- **Issue:** Chips are wider than the old outline badge because of the +1 px letter spacing. The check would have used a different `title_max` from the painter.
- **Fix:** It now uses `SongSelect.row_badge` / `row_title_max` / `BADGE_GAP` / `ROW_LEN_RIGHT`.
- **Commit:** a4c7805

**3. [Scope] SOURCE line removed and warnings line moved** (see decisions). These are not in the UI-SPEC 6 layout, and they collided with the new sections block.

**4. [Interpretation] Album.png fixture folder**
- The plan says "add one fixture song folder ... (reuse an existing fixture chart folder)". I put the art into the existing "Coral Static" folder instead of adding a song. This keeps the scenario's entry-count checks (31 + bundled) unchanged.
