# Phase 2.2 Plan 03: Wave 0 visual data (sections, meter, run stats) Summary

Charts now carry their section names and time signatures, BeatClock can list beat and bar times that follow the meter, and the D-08/D-09 maths (accuracy, grade, timing histogram, average offset text) lives in a pure tested class. A recorder collects per-hit offsets from the judge's `judged` signal. Nothing changed on screen, and song fingerprints and record ids are the same as before.

## What was built

- **ChartData**: `sections` ({time, name}) and `time_sigs` ({time, num, den}). `fingerprint()` does not read them; a test changes both and checks the fingerprint stays the same. test_bundled_songs passes unchanged.
- **ChartImporter._sections**: `[Events]` text starting with `section ` uses the same tick-to-seconds conversion, delay and clamp as `_solos`. Names lose control characters, whitespace runs become one space, names are trimmed and cut to 64 characters, and empty names are skipped. Entries are deduplicated, sorted and capped at 256 (T-02.2-05, T-02.2-06). All 5 bundled charts give 6 to 10 sections.
- **ChartImporter._time_sigs**: `TS n [exp]` becomes den = 2^exp, with num clamped to 1..32 and exp to 0..5 (T-02.2-07). If two TS events share a tick, the last one wins. A default 4/4 is added at the start, and the list is capped at 256.
- **BeatClock.beats_between**: returns quarter-note beats in [t0, t1] as `[{time, bar}]`. Bars last num*4/den quarter beats, each TS change starts a new bar, and the count carries on across tempo changes. Negative (lead-in) time extends the grid backwards. Output is capped at 4096 entries. `beat_at` and `time_at_beat` are public helpers that convert between song time and beat number.
- **RunStats**: implements D-08 accuracy (-1 when nothing was judged), "98.4%" / "--.-%", grades S/A/B/C/D/-, and grade_rank 5..0. The 28-bin histogram (5 ms, -70..+70) is computed in integer microseconds, so -65.1 ms goes in bin 0, -65.0 ms in bin 1, and +70 ms in bin 27. Also provides the rounded mean in ms and the summary text.
- **HitOffsetRecorder**: `attach(judge)` connects to `judged` and keeps error_s for PERFECT and GOOD (compared against `InputJudge.Judgment`). MISS is only counted. Also has `offsets()`, `counts()`, `reset()` and `detach()`, and attaching again never counts a hit twice. Tests use a fake emitter with the same signal signature.
