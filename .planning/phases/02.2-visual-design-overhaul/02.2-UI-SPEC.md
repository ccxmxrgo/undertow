### Why Oxanium (D-03, recorded reason)

Measured from the font files this session (V):

| Candidate | Digit advances (per 1000 em) | Tabular figures | Verdict |
|-----------|------------------------------|-----------------|---------|
| **Oxanium** | all digits 578 | **yes, by default** | **Chosen** |
| Chakra Petch Bold | 382..652 | no (no `tnum` feature) | would need per-digit cell layout |
| Rajdhani Bold | 334..542 | no | narrow; weak at 96 px |
| Orbitron | 391..834 | no | very wide (8-char wordmark > 1300 px at the wordmark height), sci-fi cliche |
| Exo 2 | not measured | | rounded humanist, less "instrument" |

1. **No layout shift for free (S-4):** every digit has the same advance (578/1000 em), so live numerals (streak, depth, accuracy, timers) never jitter. At 96 px a digit cell is 55.5 px, at 40 px 23.1 px.
2. **Shape language:** square, chamfered letterforms match the chamfered glass panels and sonar-console instruments of this spec. It reads "submarine console", not "arcade racer".
3. **Width:** compact enough that the "UNDERTOW" wordmark fits a 960 px box with tight letter fit and "12,345" at 40 px is 125 px, so the gauges fit their consoles.
4. **Glyph coverage checked:** `×` (U+00D7), `·` (U+00B7), en dash, minus, `+`, `%`, `,`, `.` are present. Arrow and geometric glyphs (U+2191, U+25B2) are **not**: draw arrows and triangles as polygons (existing rule).
5. One 44 KB variable file. If `variation_opentype {"wght": 700}` does not take effect (test: the advance of "M" at 700 differs from 400), fall back to the static `Oxanium-Bold.ttf` from `github.com/sevmeyer/oxanium` (same OFL).

## 2. Spacing, Edges, Radii

Spacing scale (multiples of 4), tokens `Palette.SP_*`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4 | Glyph-to-text nudges, chip inner gaps, bar gaps |
| sm | 8 | Gap between stacked buttons (pitch = height + 8), chip padding vertical, focus marker inset |
| md | 16 | Panel inner gaps, tile gaps, caption-to-value gap |
| lg | 24 | Panel padding, gauge-to-readout gap |
| xl | 32 | Gap between panels; outer frame margin |
| 2xl | 48 | Compact button and row height; column gaps |
| 3xl | 64 | Screen-edge padding; menu button height |

Results screen side padding is written as 3xl + xl (64 + 32 = 96 px); there is no separate token. Exceptions (declared): menu/pause/fail/results buttons are 64 tall with a 72 pitch; song-select list keeps its 80 pitch (02-UI-SPEC); difficulty tiles are 96 tall; histogram bars are 13 px with a 4 px gap (17 px pitch, 28 bins in 476 px). Board coordinates come from `Trench` and are not on the grid. Strokes (1, 2, 3, 4 px) are not spacing.

**Clean-edge rule (01.2) is replaced** (SPEC "changed prior decisions"): the cockpit frame and its consoles may occupy the screen edges. The **note-path keep-out** (section 7.1) is the new hard rule.

Edges and corners (tokens `Palette.EDGE_*`, `Palette.CUT_*`):

| Token | Value | Use |
|-------|-------|-----|
| EDGE_HAIR | 1 px | Tube outlines, inner rings, dashed socket |
| EDGE | 2 px | Panel/button edge, chips, dividers |
| EDGE_FOCUS | 2 px edge at 100% + 4 px marker bar | Focus (section 4.3) |
| CUT_SM | 8 px chamfer | Buttons, chips, tiles, slider thumb |
| CUT_MD | 12 px chamfer | Panels, dialogs, album cover frame |
| CUT_LG | 64 px chamfer | Cockpit console inner-top corner |
| Bracket | 20 px arms, 2 px, `SONAR` 80% | Panel corners that are **not** chamfered |

Chamfer rule: **top-left and bottom-right are cut; top-right and bottom-left carry corner brackets.** Implemented with `StyleBoxFlat` `corner_radius_top_left = corner_radius_bottom_right = CUT`, other radii 0, `corner_detail = 1` (one segment = a straight 45 degree cut). No rounded corners anywhere.

### 4.3 Focus marker (one per screen, `UiKit.FocusMarker`)

- A `SONAR` bar 4 px wide x (button height - 16) at x+8 inside the focused control, plus a 12x16 caret triangle (polygon) 12 px outside the left edge, pointing right.
- When focus moves, the marker glides to the new control: position tween `DUR_FAST` cubic-out. The focused edge glow breathes 20% to 32% over 1.6 s (sine).
- Reduce motion: no glide (jumps), no breathing (static 28%).
- Focus is never colour alone: marker bar + caret + brighter edge + text colour change. Contrast `SONAR` vs `ABYSS_900` 11.7:1.
- Keyboard/gamepad navigation unchanged; `ui_up/down` play the `move` blip, `ui_accept` `confirm`, `ui_cancel` `back` (section 10.4).

2. Beat lines <= 7% and bar lines <= 22% alpha; lane tint <= 14%; CRT sweep <= +5%.
3. No text on `ABYSS_500`. No `TEXT_LO` or red text without a panel/keyline behind it.
4. Colour is never the only signal: lanes = shape + number; judgments = word; hull = segment count + cracks + caption; focus = marker + caret; grade = letter; tier = rail treatment + ring + chip.
5. Readability at scroll 0.5x and 3x: harness screenshots (S-10). Gem minimum size is r 18 at the horizon (kept).

## Defaults Log (researcher choices, with reasons)

1. **Oxanium** as the display face: the only candidate with tabular digits by default (measured), which gives S-4's "no layout shift" for free; chamfered forms match the panel language.
2. **Terminal green retired everywhere, PERFECT = `SONAR_PALE`:** one teal language across menu and game (S-1); green next to lime lane 4 was also the weakest pairing for colour-blind players.
3. **Far-note core dimming retired:** x0.60 (and even x0.85) magenta fails 4.5:1 against its strip (4.48 at x0.85); ready state now reads through rim + halo.
4. **Keyline outlines** on gems and judgment text: guarantee crisp edges over bursts, bar lines and the CRT pass (S-12), and lift MISS red from 4.49 to 6.08.
5. **Additive sprites instead of WorldEnvironment glow:** Compatibility 2D is SDR, so environment glow would also bloom notes and text; sprites are per-element and cheap.
6. **CPUParticles2D:** no trails/collision gap, no first-emission shader hitch, deterministic seeds for screenshots.
7. **CRT pass only under notes:** satisfies "must not blur notes" by construction.
8. **Consoles at x 0..400 / 1520..1920 from y 600:** keeps the 58% centre band clear and stays 119 px from the board edge at the hit line.
9. **Depth stays Heading 40, streak is Display 96:** depth up to 6 characters would not fit a 96 px box in the console; the streak is the game's identity ("your streak is a torpedo").
10. **Bathymeter scale = all-Perfect estimate:** gives a stable, meaningful moving marker without changing scoring.
11. **3-arc multiplier ring with 10 notches each:** maps 1:1 to `combo_per_multiplier_step = 10` and `max_multiplier = 4`.
12. **Streak numeral always visible** (muted below 10) instead of hidden below 5: it is an instrument now; StreakCounter tests update.
13. **Intro room trimmed, replaced by a rig-boot stage with the same timings:** reasons in 9.5.
14. **No pause blur:** opaque 85% backdrop is cheaper and guaranteed readable.
15. **Gold `#FFD36B` never inside the note path:** it is close to lane-2 amber (1.18:1 luminance difference), so it is kept to consoles, results and menus.
16. **Results keeps "Back to Menu" copy** (SPEC says "Main Menu" generically) for consistency with pause and IMPLOSION.
17. **Toggle text "ON"/"OFF"** replaces "[ ON ]": the brackets were the terminal look being retired.
18. **Section banner above the vanishing point** (y 200..272): the only wide free area that never overlaps notes.
19. **Album art loaded only for the selected song**, never during scans (keeps 02's safety reasoning for scans).
20. **Glow and particle cut order** for a perf miss is pre-agreed (section 12).
21. **Grade at Display 96 inside an emblem, logo as a wordmark asset** (checker fix): UI text stays at 4 sizes; only the 01.2 intro-count exception remains.
22. **Gems drawn above bursts and judgment text** (`HighwayNotes`), bursts clipped to y >= 840, one popup per chord: feedback never hides an upcoming note.
