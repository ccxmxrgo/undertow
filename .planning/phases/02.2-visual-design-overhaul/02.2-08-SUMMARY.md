# Phase 2.2 Plan 08: Board surface and gems Summary

The gameplay board is now a lit glass surface rather than four thin cables. Four translucent lane strips (7% lane tint over the 90% highway base) fade out over the last 50 px. They have soft separators, teal outer rails and a pulsing hit line with five lane ticks. Notes are solid gems: a dark keyline, the full lane-colour core, a top-light, a white specular chevron and a rim. The rim brightens and a soft additive halo appears when the note is inside the Good window. Same-time notes get a pale chord bar. Receptors are glass pads in each lane's shape. On any press they fill with the lane colour, glow and squash (1.12 x 0.88, back over 120 ms; no squash under Reduce motion). The gems, missed remnants and lane numbers are drawn by a new HighwayNotes layer above Feedback, so bursts and judgment text in later plans can never cover an upcoming note.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] test_gameplay_smoke layering test assumed every layer is a direct child of _run_root**
- **Found during:** Task 2
- **Issue:** The test counted Arena children only under `_run_root`, and it compared indices across parents. Arena now lives under BoardRoot.
- **Fix:** The test now checks the BoardRoot order (Arena < Highway < Feedback < HighwayNotes), that BoardRoot comes before Hud, StreakCounter and PauseMenu in `_run_root`, that `nudge_target` is board_root, and it counts restart children across both parents.
- **Files modified:** tests/test_gameplay_smoke.gd (not listed in the plan's files)
- **Commit:** 7f4df46

**2. [Rule 2 - Interpretation] Halo reach and the cable_bright meaning**
- Both are recorded under decisions above. The halo follows the mockup's proportions. cable_bright is an extra brightness boost because 0 is the normal-play value set by GogglesIntro.

**3. [Rule 2] Strip-tint harness check measured against the neighbouring strip**
- The plan asked for "hue matches the lane colour direction". A 7% tint over a 90% dark-blue base does not show the lane hue on its own (amber and lime read nearly grey). So the check compares (strip - neighbour strip) with (lane colour - neighbour lane colour), plus the plan's max channel >= 0.04. It picks a depth near 0.5 where neither lane has a note or sustain (`_free_strip_depth`).

### Kept as-is

- `Palette.dim`/`NOTE_DIM` stay in Palette because song_select.gd still uses them. Only Highway stopped using them, as the plan asks. The old palette dim test became the gem rim/halo state test.
- The early/late indicator is still drawn by Highway. It moves with the Feedback restyle in a later plan.
