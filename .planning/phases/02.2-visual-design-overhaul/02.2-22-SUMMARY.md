# Phase 02.2 Plan 22: Sonar wipe screen transitions Summary

Every game screen change now goes through one `ScreenTransition` autoload. It plays a 300 ms sonar wipe:
- an ABYSS_900 disc with a 6 px SONAR_PALE rim grows from the focused control over 150 ms
- the scene swaps at full cover
- a hole grows from the same point over 150 ms to reveal the new scene

The wipe never exceeds 400 ms, never eats more than the key that skips it, and accepts input from the first frame of the reveal. Reduce motion turns it into a 160 ms cross-fade, and Low effects drops the glow. The timing core is untouched (TIMING GATE OK).

## What was built

### Task 1: ScreenTransition and sonar_wipe (TDD: a9ea34e test, e4a511c feat)
- **`shaders/sonar_wipe.gdshader`** (canvas_item, no screen texture, no colour constants):
  - It uses the signed distance from `centre` to the disc (cover) or the hole (reveal), with a 1 px anti-aliased edge.
  - The ring is drawn in `edge_color`, `edge_px` wide.
  - With `glow` on, a 28 px soft halo sits on the open side of the edge.
  - Local pixel positions come from `VERTEX`, so the wipe works in the 1920x1080 design space.
- **`src/ui/screen_transition.gd`** (autoload `ScreenTransition`, CanvasLayer 100, process mode always):
  - A full-rect ColorRect (`UiLayout.fill_rect`, mouse IGNORE, hidden when idle), with colours from Palette ABYSS_900 / SONAR_PALE.
  - A state machine with IDLE, COVER and REVEAL (cubic-in 0 -> 2200, cubic-out hole).
  - The swap uses `get_tree().change_scene_to_file`, and the reveal starts on `scene_changed`.
  - The 400 ms failsafe, `instant`, and the Reduce / Low paths.
  - Signals `started`, `swapped` and `finished`.
  - `UiKit.register_fx` and `effect_counts() -> {glow, crossfade}`.
- **project.godot:** `ScreenTransition="*res://src/ui/screen_transition.gd"` in [autoload].

### Task 2: Call sites and harness (b0fd2c3)
- **Wired to the wipe:**
  - main_menu.gd and settings_screen.gd `_go`: the navigate seam stays in front, so unit tests are still synchronous.
  - song_select.gd `_go`, for both the dive and Esc back. The 0.15 s DiveFade pane is gone, and the goggles intro still follows in Gameplay.
  - gameplay.gd `go_to_menu` and `go_to_song_select`.
  - calibration_wizard.gd `_leave`.
- **Unchanged:**
  - Retry (QUICK intro in place, no scene change).
  - drift_harness.gd.
- **Harness (sc_polish, after the practice dive):**
  - Menu -> Song Select with Enter: "screen transition finishes within 400 ms", measured from the Enter press to `ScreenTransition.finished`, with the wipe-only duration in the detail.
  - Esc back to the menu, with two shots on a frozen clock (cover r 652, reveal r 596).
  - Menu -> Song Select again: on the first frame of the reveal a list key is pressed (Down, or Up when the selection is the last row), and the check asserts the selection moved: "input works from the start of the reveal".

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A slow scene load stretched the wipe toward the cap**
- **Found during:** Task 2, polish run 2 (Enter to finished 422 ms, wipe 386 ms at 20 fps)
- **Issue:** The reveal timed 150 ms from `scene_changed`, so the new scene's synchronous load added straight onto the 300 ms.
- **Fix:** The load time (swap request -> scene_changed) comes out of the reveal, down to half of it. Two unit tests were added. The next run measured 349 ms from Enter to finished, and the wipe itself took 314 ms.
- **Files:** src/ui/screen_transition.gd, tests/test_screen_transition.gd
- **Commit:** b0fd2c3

**2. [Rule 3 - Blocking] `PRESET_FULL_RECT` is banned in src/ui** (test_review_fixes)
- **Fix:** The rect uses `UiLayout.fill_rect`.
- **Commit:** b0fd2c3

**3. [Rule 1 - Harness bug] The reveal input check pressed Down on the last selectable row**
- **Issue:** The calibration track is the last selectable row, followed by a divider, so Down could not move.
- **Fix:** The check now presses Up in that case.
- **Commit:** b0fd2c3

**4. [Interpretation] What the cover consumes, and what the reveal does with a press**
- UI-SPEC 9.7 says "the new screen accepts input as soon as the reveal phase starts", so only the cover consumes input.
- A press in the reveal reaches the new screen and also ends the reveal visually.
- The press that started the wipe (same frame) does not skip it. Otherwise a scene `_input` that navigates would skip its own wipe, since the autoload gets `_input` after the scene.

**5. [Interpretation] Harness ordering**
- The transition block runs in sc_polish after the practice dive, not at the menu start. This leaves the menu-music and practice checks untouched.
- The two shots run the wipe on a frozen clock (`clock_fn`) so they are deterministic at any frame rate. The timing check uses the real clock.
