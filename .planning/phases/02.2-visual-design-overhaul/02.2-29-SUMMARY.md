# Phase 02.2 Plan 29: Gamepad settings and calibration (G3 part 2) Summary

Settings, rebinding, the sliders, the Background row and the calibration wizard can now be used with a controller alone, and a pad-only player can no longer get stuck. A harness scenario called `pad` walks the whole menu flow (menu -> song select -> dive -> pause -> settings overlay -> resume -> quit confirm -> menu -> settings -> calibration -> skip) using only joypad events, and every step passes.

## Root causes

1. **Settings focus navigation was geometric.** Going down happened to work. Going up from Back landed on a volume slider, because the wide sliders win Godot's nearest-control search, and every row after that was wrong. Fix: `link_focus_rows()` sets each row's Up/Down neighbour to the same column of the next row. Disabled buttons are skipped. The links are rebuilt when library rows change. Tab order is not changed.
2. **A listening keyboard rebind cell ignored the pad.** Pad events went past the cell, so D-pad moved focus away while the cell was still listening, and B left the whole screen through `ui_cancel`. Fix: pad B cancels listening on a keyboard cell, and every other pad event is swallowed.
3. **Stick on a StepSlider moved the wrong way and moved repeatedly.** A +X stick event also matches `ui_left` as "not pressed", and `event.is_pressed()` is true for any |value| >= 0.5. Because of this, pushing the stick right stepped the slider LEFT, once per motion event (about 4 steps per push). Fix: use `is_action_pressed(action)` and latch the direction until the stick returns to centre.
4. **Background row flipped once per stick motion event.** Same latch fix as the slider.
5. **Calibration visual step:** D-pad Down from the slider did not reach Accept. Fix: explicit per-step focus links (slider <-> Accept / Retry, then the row continues to Skip for now).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] StepSlider stepped the wrong way on a stick push**
- **Found during:** Task 1
- **Issue:** `event.is_pressed()` on a JoypadMotion that matches the opposite `ui_*` action (as "not pressed") is still true, so pushing right stepped left, once per motion event.
- **Fix:** Direction comes from `is_action_pressed(action, true)`, with a per-push latch.
- **Files modified:** src/ui/step_slider.gd
- **Commit:** c0369d8

**2. [Rule 2 - Consistency, requested by the orchestrator] Fail screen B = Back to Menu**
- The plan did not cover it. The fail screen ignored B, while results maps B / Esc to Back to Menu. `FailScreen._unhandled_input` now emits `menu_pressed` on `ui_cancel` once the buttons are enabled, so it stays inert during the squash and fade (WR-06). Esc now does the same, which matches the results screen. Gameplay only reads Esc as pause while RUNNING, so there is no conflict.
- **Files modified:** src/ui/fail_screen.gd
- **Commit:** c0369d8

**3. [Rule 3 - Tooling] Test helpers**
- `_expected_rows` in the walk test skips disabled buttons, matching `focus_rows()`. The stick slider test starts at Master 50% so there is room in both directions.

Observed but not changed: the gdUnit CLI stops running a suite's remaining test cases after the first test case that fails (seen with this suite during RED). A green run is not affected. This is logged in deferred-items.md.
