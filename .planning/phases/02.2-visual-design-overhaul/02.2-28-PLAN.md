## Phase Goal

**As a** player diving with friends, **I want to** every screen to look like one finished deep-sea cockpit game, with a rich board and instrument HUD that react to my hits and the music, **so that** UNDERTOW stops feeling like "a road and some numbers" while timing stays exactly as tight.

<objective>
Gap G3, part 1 of 2 (02.2-HUMAN-UAT.md): "The game is only playable with a controller when on a song. Menus and other stuff don't work."
Root cause found during planning (headless InputMap dump in this repo): Godot's built-in ui_accept has only Enter / KP Enter / Space and ui_cancel only Escape, so A and B do nothing on Button-based screens; ui_up/down/left/right already have D-pad + left stick; pause already has Start (button 6). Song select works only because it reads pad buttons itself.
This plan fixes the input map and makes the main flow screens pad-operable: main menu (+ device prompt), song select, results, fail, pause, confirm dialogs, intro. Plan 29 covers settings, rebind cells, sliders, calibration and the pad-only harness walk.

Output: project.godot input overrides, pad test helper, two test files, fixes in the listed screens.
</objective>
