# Phase 02.1 Plan 04: Analysis pipeline (decode, separate, beats, onsets, pitch) Summary

`autochart.py analyze` turns one audio file into all the measured audio facts in one command: stems lined up to 0.000 ms, refined beats, audible onsets per stem and Basic Pitch pitch per onset. Each stage leaves an inspectable JSON or WAV under build/autochart/<id>/. All three custom songs have been analysed, and the numbers match the research measurements.

**Against RESEARCH:**
- Sea Shanty: 200.00 BPM constant, 14 repaired missed beats, −6.5 ms global shift and "other" about 100% pitched. All identical to the research.
- HRT: research gives "85.7 BPM" as the raw median IBI (beat_this frames are 20 ms, so 0.70 s reads as 85.71). It gives a fit of 85.996 BPM and a range of 84.8–86.9. Our refined 86.005 matches the fit. The phase shift is −9.3 ms, against research −10.5 / −9.5. "other" is pitched on 47%, inside research's 36–47%.
- INVISIBLE: research gives "115.4 BPM" as the raw median IBI, which is frame-quantised, and a local smoothed range of 112.4–115.0. Our refined median is 114.0, inside the plan band of 111..117. The first downbeat is 1.446 s (research 1.44 s). The phase shift is −1.5 ms (research −2.4).
- Audible+loud counts are before ranking, density targeting and merging, which happen in plan 05. INVISIBLE "other" has many candidates (10/s) at this stage, which is expected: ranking down to 3 n/s happens in build_expert.
- Sea Shanty bass and vocals are near-silent stems (about 0% energy). They still report many "loud" onsets because the silence gate is relative to the stem's own 95th percentile. That gate is the research's own rule. Plan 05 must pick the stem first (Sea Shanty = other only).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Refined beats before 0 s**
- **Found during:** Task 3 (HRT run)
- **Issue:** beat_this put a beat at 0.000 s. The −9.3 ms local phase correction moved it to −1.1 ms, and a downbeat was snapped onto it, which left a negative beat and downbeat time in beats.json.
- **Fix:** Added `beats.drop_before_zero` after snapping, with a unit test. The HRT first downbeat is now 2.789 s, and 226 beats remain.
- **Files modified:** tools/autochart/stages/beats.py, tools/autochart/tests/test_beats.py
- **Commit:** c2bae67

**2. [Rule 1 - Test bug] Constant-tempo "no wobble" assertion**
- **Found during:** Task 2 GREEN
- **Issue:** The RED test asserted an IBI range below 2.1 ms. With the alternating ±1 ms jitter the plan prescribes, the input itself already has a 4 ms IBI range.
- **Fix:** The test now asserts that the IBIs are unchanged by the global shift. This is the actual Pitfall 3 property.
- **Commit:** 68caeed

**3. [Rule 2 - Safety] `.gitattributes` for audio**
- The repo has core.autocrlf=true and no .gitattributes. Git's binary detection already left the MP3s untouched (blob = raw hash), but the rule is now explicit: `*.mp3 *.wav *.ogg binary`.
- **Commit:** e1d2276

**4. [Plan detail] Extra CLI option and keys**
- `analyze --stems` (default other drums bass vocals) selects the stems for the onsets and pitch stages.
- beats.json also stores `resid_p90_ms` and `mix_onsets_used`. onsets_<stem>.json also stores `pitched_share_all` and `bp_notes`. The contract keys are unchanged.
- stem_onsets takes an optional `mix_onsets=` argument so the mix D3 (delta 0.03) runs once per song instead of once per stem.
- For songs shorter than about 50 s, the lag checks fall back to a shorter correlation window (`decode.lag_segment`).

**5. [Tracking] Requirements**

- STEM-03 (generate a 4-lane chart from one stem) is not done until plan 05 writes the chart, so it stays Pending.
