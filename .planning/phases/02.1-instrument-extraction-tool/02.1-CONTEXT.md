<decisions>
## Implementation Decisions

### Pipeline shape
- **D-01:** The pipeline is a dev-side Python tool under `tools/autochart/`, run in an isolated venv with a supported Python (system Python is 3.14; use `uv` or a pinned 3.11/3.12). Godot is not involved except to decode audio and measure sync. Always run it isolated (`-I`), and keep downloaded models out of the repo (cache dir in `.gitignore`).
- **D-02:** Stages: decode → stem separation → beat/downbeat tracking → onset + pitch per note on the chosen stem → quantize to the tempo grid → contour lanes → Expert → reductions → sections/solo/preview → write `notes.chart` + `song.ini` → sync report. Each stage writes an inspectable JSON intermediate (`build/autochart/<song>/`), so one stage can be re-run without re-separating.
- **D-03:** Research (STEM-01) picks the concrete libraries by measuring on the 3 songs. Recommended starting candidates: htdemucs / htdemucs_ft (separation, CPU), beat_this or madmom (beats/downbeats), Basic Pitch (note onsets + pitch + offsets on the stem), with a librosa onset/pyin fallback. No NVIDIA GPU was detected, so CPU time matters but is not a blocker (offline, one-off per song).
- **D-04:** Determinism: the committed `notes.chart` is the source of truth. Tests check the committed charts (structure, density caps, contour rules, sync report numbers stored alongside). They don't re-run ML separation. The pipeline's post-separation stages (from intermediates onward) must be deterministic, and are unit-tested on synthetic note lists.

### Chart style (Clone Hero imitation)
- **D-05:** Write 4-lane charts directly as `N 0..3` in `[EasySingle]..[ExpertSingle]`. Verify the importer maps them as identity under the existing 5→4 rule (G,R,Y,B → lanes 1-4; no Orange used). Resolution 192.
- **D-06:** Contour lane rule, density caps, snap rule (1/16 vs 1/12, ≤ 15 ms snap) and the reductions are exactly as in SPEC requirements 3, 4 and 6.
- **D-07:** Instrument per song: Sea Shanty 2 = lead melody. INVISIBLE = lead guitar/synth ("other"), switching to bass by section if the lead is too sparse. HRT = most prominent melodic stem, chosen by research with the reason recorded.
- **D-08:** Sections come from the detected structure (novelty/self-similarity boundaries, snapped to bars) and get generic names (Intro, Verse 1, Chorus 1, ..., Outro; use "Section N" if unsure). Solo = the densest 4–8 bar instrumental stretch. Preview = start of the loudest section.

### Sync gate and verification
- **D-09:** Sync is measured on the game's own decoded stream (existing `align` harness scenario → `build/playtest/align_<id>_decoded.wav`), never on the source file. The `delay` in song.ini is fitted to the median note-to-onset error. Gates as in SPEC requirement 5 (median ±5 ms, ≥ 90% within ±25 ms of a stem onset, ≥ 80% of a mix onset, live-record cross-check ≤ 3 ms).
- **D-10:** Extend `tools/charting/grid_offset.py`-style stdlib scripts, or add a `note_sync.py`, so the gate is a repeatable command. Record its output in `tools/autochart/README.txt` and the phase UAT.
- **D-11:** If HRT can't reach the gate, ship its best result flagged in UAT. It doesn't block the other songs.
