# Phase 02.1 Plan 01: Sync gate and reproducible environment Summary

This plan builds the tools that later plans use to prove sync. There are two pinned uv venvs that rebuild with one PowerShell command. The windowed align harness no longer hangs. `note_sync.py` measures a chart through the game's own ChartImporter and decoded stream, against D3 onsets, and prints a chance level next to each percentage. It reproduces the Neversoft professional baseline within 1 point: 55.3% / 74.0% against research's 54.5% / 73.5%.

## Important finding for later plans

The user called the April chart unsynced in UAT item c, yet with mix only it reaches **PASS_BASELINE**: 78.5% within ±25 ms against 9.9% chance. Its fixed 120 BPM grid is in phase with the audio, and April's synth hits mostly fall on 8ths. So the mix-only metric cannot tell "on the beat" apart from "on the instrument that plays". Later plans (02.1-03..08) should always gate new charts with `--stem` and `--beats`, and keep the ear check as the final word. The README records this. The verdict logic stays as the plan specified, with the stem check applied only when `--stem` is given.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `.gitignore` already ignored every `reports/` directory**
- **Found during:** Task 1
- **Issue:** The existing `reports/` rule, meant for gdUnit output, would have ignored `tools/autochart/reports/`, so the baseline reports could not have been committed.
- **Fix:** Added `!tools/autochart/reports/` next to `__pycache__/`.
- **Commit:** 51fb1f2

**2. [Rule 2 - Correctness/Safety] `uv python install` wrote shims into the user's ~/.local/bin**
- **Found during:** Task 1
- **Issue:** By default uv installs `python3.x.exe` shims outside build/. That breaks the "nothing outside build/autochart" rule. The existing shims there came from the research session; this run added none.
- **Fix:** Added `--no-bin` to the install call.
- **Commit:** 51fb1f2

**3. [Rule 3 - Blocking] `python -I` does not put the script directory on sys.path**
- **Found during:** Task 3
- **Issue:** On Python 3.11+, `-I` implies `-P`, so `from stages import d3` would fail.
- **Fix:** note_sync.py now inserts its own trusted directory, tools/autochart, explicitly.
- **Commit:** 622b72d

**4. [Plan detail] `mido` dropped from requirements-a.txt**
- The research venvA had mido installed by hand for MIDI reading. The pipeline does not need it: mid_notes.py uses only the standard library. venvB keeps mido because it is a dependency of basic-pitch / pretty-midi.

**5. [Plan detail] "423 asserted by the existing test"**
- tests/test_bundled_songs.gd only asserts `> 100` Expert notes for April and has no literal 423. The dump gives 423, which matches the plan's figure.

**6. [Plan detail] The reproduction is within tolerance but not exact**
- Our numbers are 55.3 / 74.0, against research's 54.5 / 73.5. The chance values differ slightly as well: 39.7 vs 37.7 and 43.2 vs 43.1. The cause is that the chance shifts are drawn with `random.Random(0)` rather than research's RNG, and the mix-sum and resample paths differ a little. All values are inside ±1.

**7. [Tracking] STEM-06 not marked complete**
- The plan frontmatter lists STEM-01 and STEM-06. Only STEM-01 is marked complete in REQUIREMENTS.md. STEM-06 (three songs bundled and synced) is delivered by plans 02.1-05/06, and this plan only provides its gate. `requirements.mark-complete` had ticked both, so STEM-06 was reset to Pending by hand.
