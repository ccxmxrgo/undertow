    - MemTransport: hub.make_host() gets id 1 and make_client() gets 2, 3, 4. A client connects, the auth packet reaches the host as auth_request, then complete_auth on the host emits peer_joined(id) on the host and `connected` on the client.     - Two runs with the same seed produce identical delivery logs.

`ClockSync` (class_name, RefCounted) follows RESEARCH Pattern 3 exactly, with these additions: rtt percentile helpers and `reset()`. It never reads Time; all ticks are passed in, as in the house style.

`NetTransport` (class_name, RefCounted) is the seam base, documented like EventChannel. It names the ENet implementation (04-06) and the MemTransport.
- Signals: `packet(peer: int, bytes: PackedByteArray)`, `peer_joined(peer: int)` (host side, after auth), `peer_left(peer: int)`, `auth_request(peer: int, bytes: PackedByteArray)` (host side), `auth_reply(bytes: PackedByteArray)` (client side), `connected` (client: auth accepted), `connect_failed(code: String)` (client: "timeout"/"resolve"/"refused"), `server_lost` (client).
- Methods with safe no-op defaults: `send(peer: int, bytes: PackedByteArray, reliable: bool = true) -> void` (reliable means channel 0, unreliable means channel 1, D-01), `send_auth(peer: int, bytes: PackedByteArray)`, `complete_auth(peer: int)`, `refuse_auth(peer: int, reply: PackedByteArray)`, `disconnect_peer(peer: int)`, `set_refuse_new(on: bool)`, `poll(now_s: float)`, `close()`, `unique_id() -> int`, `is_host() -> bool`, `peers() -> PackedInt32Array`.
- Host id is always 1, as in Godot.

`MemTransport` extends NetTransport with an inner `class Hub`. The Hub holds a virtual clock, a seeded RandomNumberGenerator (`hash([seed, "mem"])`), per-link settings via `set_link(id, latency_s, jitter_s, loss)`, `advance(now_s)` which delivers everything due in due-time order (stable by enqueue index), and `drop_peer`, `stall` and `pending_count`. Endpoints come from `hub.make_host()` and `hub.make_client()`. `client.connect_to_host()` runs the simulated auth flow: the client's first send_auth payload becomes `auth_request` on the host, `complete_auth` emits `peer_joined`/`connected`, and `refuse_auth` delivers `auth_reply`, then the hub disconnects that client. Use method callables, not lambdas, for long-lived connections (CR-02).

Write the tests first: tests/test_clock_sync.gd and tests/test_mem_transport.gd (ordering, FIFO under jitter, loss only on unreliable, drop/stall/close semantics, the auth flow, seeded reproducibility).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote peer -> NetCodec.decode | every byte from the network is untrusted, including bytes from the host (Pitfall 6) |
| transport -> game code | only validated Dictionaries cross |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Elevation of privilege | NetCodec.decode | mitigate | only bytes_to_var is used (no _with_objects). A grep gate in done criteria keeps it that way. allow_object_decoding stays false (04-06) |
| T-04-02 | Denial of service | oversize or deeply nested packets | mitigate | MAX_PACKET is checked before decode. Arrays, batches and strings are capped. Nesting depth is at most 3. The fuzz test proves there is no crash |
| T-04-03 | Tampering | NaN/INF/out-of-range times and indices | mitigate | is_finite plus range checks on every time. Note indices are checked against ctx.note_count. Seats are limited to 0..3 |
| T-04-04 | Spoofing | messages valid in the wrong direction | mitigate | FROM_CLIENT/FROM_HOST whitelists are applied with ctx.from_host |
| T-04-05 | Tampering | player names with control characters | mitigate | clean_name charset [A-Z0-9 _-], 12 chars |
| T-04-SC | Tampering | package installs | accept | none in this phase (engine built-ins only; RESEARCH Package Legitimacy Audit is empty) |
</threat_model>
