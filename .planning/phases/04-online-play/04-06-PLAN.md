  <action>
Create `ENetTransport extends NetTransport`. It owns its own `SceneMultiplayer` (`api`) and `ENetMultiplayerPeer` (`peer`). The header documents the engine facts: 2 channels; `server_relay = false` (D-22); `allow_object_decoding` stays false; `auth_timeout = 3.0`; `refuse_new_connections` for set_refuse_new; and the ENet server peer timeouts `set_timeout(32, 4000, 10000)` per connected ENetPacketPeer (D-17).

API:
- `host(port) -> Error` calls create_server(port, 3, 2).
- `join(address, port) -> Error` calls create_client(address, port, 2). A resolve failure maps to connect_failed("resolve").
- `send(peer, bytes, reliable)` calls `api.send_bytes(bytes, peer, mode, channel)`, with mode/channel = reliable/0 or unreliable/1.
- Auth goes through `api.auth_callback`, which emits `auth_request(peer, data)` (host side) and `auth_reply(data)` (client side). `send_auth` and `complete_auth` map to the api methods. `refuse_auth(peer, reply)` does send_auth(reply), then disconnect_peer after one poll so the reply flushes.
- Map `peer_connected` to peer_joined (host side) and connected (client side), `peer_disconnected` to peer_left, `server_disconnected` to server_lost, and `connection_failed` to connect_failed("timeout").
- `poll(now_s)` calls api.poll().
- `close()` closes the peer.
- `rtt_ms(peer) -> int` reads `ENetPacketPeer.get_statistic(PEER_ROUND_TRIP_TIME)` where available. It is debug only.
- It never blocks and never throws; error codes are returned.

tests/test_enet_transport.gd runs a host and 2 clients as separate ENetTransport instances in one process, on a high random port (49000-49900) so a running game cannot collide. It steps `poll` in a loop with small `await get_tree().process_frame` waits and a 5 s cap. Test cases:
- (a) The auth handshake is accepted by complete_auth.
- (b) A refusal reply reaches the client, then it is disconnected.
- (c) Bytes flow both ways on both channels and arrive intact.
- (d) A third client beyond max_clients 3 is not accepted (create the host with max 1 in the test, to keep it fast).
- (e) Client close is seen by the host as peer_left. Host close is seen by the client as server_lost.

If assumption A5 fails (send_bytes needs a tree-bound API), attach each api with `get_tree().set_multiplayer(api, node_path)` on per-peer child nodes inside ENetTransport. Document which path worked in the SUMMARY.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet/VPN peer -> ENet socket -> NetSession | untrusted bytes, joins and auth payloads |
| host -> clients | clients accept control messages from peer 1 only |
| peer song key -> local library | fingerprint lookup only, never a path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-17 | Spoofing | client forging host messages | mitigate | server_relay=false (star topology). Clients drop packets with sender != 1 |
| T-04-18 | Elevation of privilege | object decoding over ENet | mitigate | raw send_bytes plus NetCodec only. allow_object_decoding is never set true (grep gate) |
| T-04-19 | Denial of service | join spam / connection floods | mitigate | max_clients 3, auth_timeout 3 s, refuse_new outside LOBBY, ping rate limit and strikes |

| T-04-21 | Information disclosure | file paths leaking via song match | mitigate | only fingerprint + versus_sig + title/artist cross the wire (D-11) |
| T-04-22 | Information disclosure | unencrypted ENet over port-forward | accept | low-value game data. Tailscale/ZeroTier encrypt. Documented in ONLINE_SETUP.md (04-18) |
