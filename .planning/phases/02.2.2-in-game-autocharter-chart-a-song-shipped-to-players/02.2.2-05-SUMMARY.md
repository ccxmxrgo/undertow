It writes only ASCII JSON events to stdout and everything else to log.txt. It has a stem cache, cancel safety and stable error codes. `selftest` proves that the models load and run offline. On synth_wave_april the job ran end to end with the dev venvP interpreter (merged pack decision), and dev `chart` output did not change.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The stdin watchdog deadlocked the job on Windows**
- **Found during:** Task 2, first e2e run. There were no events for 634 s, 0 CPU time, and the process was stuck before `start`.
- **Issue:** the watchdog thread did a blocking read on fd 0 (a synchronous pipe). Windows serialises every other call on that file object (fstat/isatty/GetFileType) behind the pending read, so an import that touched stdin hung.
- **Fix:** the watchdog reads a private `os.dup(0)`, and fd 0 and sys.stdin are re-pointed at NUL. The watchdog starts only when stdin is a pipe (S_ISFIFO), so DEVNULL or a TTY never triggers exit 4.
- **Commit:** 061dc03

**2. [Rule 2 - Diagnostics] faulthandler writes to log.txt**
- A native crash (exit code "crash" in the runner) now leaves a Python stack in the log the error dialog points to.
- **Commit:** 061dc03
