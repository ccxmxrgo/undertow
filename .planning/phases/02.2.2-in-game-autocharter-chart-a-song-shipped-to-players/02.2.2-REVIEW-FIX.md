## Fixed Issues

### CR-01: The pinned hash is checked on one read and extraction uses another (TOCTOU)

**Files modified:** `src/autocharter/pack_installer.gd`, `tests/test_pack_installer.gd`
**Commit:** 347a3cc
**Applied fix:** Install from Folder now runs the verify worker with `copy_from`. The worker streams the chosen file into `dl/<part>.part`, hashes exactly the bytes it writes, and renames the file to `dl/<part>` only when both size and hash match. Extraction reads only the copies in dl/, and nothing in the player's folder is ever written. The regression test swaps the source zip for a hostile one once extraction starts. It passes with the fix. Against the old code it failed: the installed file read "genuineEVIL".

### WR-01: A cancel that races the end of the job reports "Charting stopped" although the song was installed

**Files modified:** `src/autocharter/autochart_runner.gd`, `src/ui/chart_song_screen.gd`, `tests/test_autochart_runner.gd`, `tests/test_chart_song_screen.gd`
**Commits:** 82ed8ba, 5c8dd8b (test string tidy)
**Applied fix:**
- `cancel()` now acts only while the child is alive.
- `_finish` treats a received `done` event with no error event as finished, whatever the exit code, once a cancel has raced it.
- The screen disables Cancel at the `install` stage, closes an open stop dialog and ignores Esc. Cancel is enabled again when the next job starts.

Status: fixed. Requires human verification of the logic.

### WR-02: `_verify_task` can spin forever on a read error or short read

**Files modified:** `src/autocharter/pack_installer.gd`, `tests/test_pack_installer.gd`
**Commit:** cb45601
**Applied fix:** The hash loop moved into a new `PackInstaller.hash_stream`. It counts the bytes it has read and returns `mismatch` when a read comes back empty or `get_error()` reports a failure. The test feeds it a file shorter than the claimed size.

### WR-03: Extraction ignores write failures

**Files modified:** `src/autocharter/pack_extractor.gd`, `tests/test_pack_extractor.gd`
**Commit:** 21b6ec6
**Applied fix:** Each entry's data must now be the size its central-directory record claims (`read_failed` otherwise). After each write the code checks the `store_buffer` result, `get_error()` and the file position (`write_failed` otherwise). The test patches a central-directory size, and the old code wrote an empty file and still reported ok.

### WR-04: The recursive-delete root guard follows junctions and symlinks (with IN-08)

**Files modified:** `src/autocharter/pack_paths.gd`, `src/autocharter/pack_installer.gd`, `src/autocharter/work_cache.gd`, `src/autocharter/pack_extractor.gd`, `tests/test_work_cache.gd`
**Commit:** 7292c25
**Applied fix:** There is now one `AutochartPaths.rm_tree`. It removes a junction or symlink as a link (`DirAccess.is_link`) and never descends into it. It also checks the top-level path. `AutochartPaths.norm` replaces the four `_abs` copies, and the two `_rm_tree` copies are gone. `size_bytes` skips links, so the freed-bytes figure matches what was actually deleted.

The test builds a junction with `mklink /J` and checks that the target's files survive.

**Note for the human:** this test also passes on the old code. Godot 4.7.2's `DirAccess.get_files_at` and `get_directories_at` cannot open a junction ("Couldn't open directory"), so the old `_rm_tree` already removed only the link. The fix is still defence in depth for real symlinks. Those could not be created here because the account lacks SeCreateSymbolicLinkPrivilege, so that case was not exercised. A probe folder, `%TEMP%\sltest` (holding a dummy `tgt\a.txt`), was left behind because the sandbox blocked `rm -rf`. It is safe to delete.

### WR-05: Godot compares paths case-sensitively against paths the Python side resolved

**Files modified:** `src/autocharter/pack_paths.gd`, `src/autocharter/work_cache.gd`, `src/ui/chart_song_screen.gd`, `tests/test_work_cache.gd`, `tests/test_chart_song_screen.gd`
**Commit:** b97be5b
**Applied fix:**
- `is_under_root` and the prune `protect` match now compare through `AutochartPaths.path_key` / `same_path`, which lowercase both paths on Windows.
- The screen rebuilds the reported work dir under `work_root()`, but only when the reported path is a `w_*` folder sitting directly in it.
- Play Now builds the song id from the library's `songs_dir()` plus the reported `slug`. The slug must match `^[a-z0-9_]{1,48}(_\d{1,2})?$`, otherwise no selection is set.

**Commit:** e02d8ce
**Applied fix:** `parts_to_fetch` now also adds every part that shares a root with a changed part, following the shared roots until nothing new is added. The test splits app into -a / -b parts and updates only -a. Both files survive.

### WR-07: No retry when renaming the staging folder fails

**Files modified:** `src/autocharter/pack_installer.gd`, `tests/test_pack_installer.gd`
**Commit:** 783d6e7
**Applied fix:** Both finalize renames go through `_rename_with_retry`. It makes 10 attempts 500 ms apart on the worker thread and checks the cancel flag between attempts. Tests can inject `rename_attempts`, `rename_retry_ms` and `rename_fn`. Two tests cover this: one where the rename recovers after two failures, and one where it gives up after the last attempt.

### IN-02: The 2 GiB free-space requirement is too small for a reinstall

**Files modified:** `src/autocharter/pack_installer.gd`, `tests/test_pack_installer.gd`
**Commit:** 11aab20
**Applied fix:** A new `required_free_bytes(todo, full)` estimates the peak space needed:
- the download plus the unpacked size, plus the old tree while it is still in place;
- for partial updates, the unpacked size scaled by their share of the download;
- for full installs, never less than 2 GiB.

Partial updates are now checked too. When more than 2 GiB is needed, the message shows the real figure.

### IN-03: A killed install in the cross-volume path leaves junk folders in Songs [pack rebuild]

**Files modified:** `tools/autochart/stages/job.py`, `tools/autochart/tests/test_job.py`
**Commit:** df7e683
**Applied fix:** `_install_copy` writes an `.autochart_installing` marker into its temp folder and removes it once `notes.chart` is in place. Before choosing a name, `install_atomic` sweeps `.tmp_<slug>` folders and marked `<slug>` folders that have no `notes.chart`. Unmarked folders are never touched. This differs from the review's suggestion of "folders without notes.chart", which could delete a player's own `notes.mid` song. The tests simulate a kill and also cover a mid-only folder, which is left alone.
