# Phase 02.2.2 Plan 03: Pack installer Summary

The game can now install the Autocharter pack safely. It downloads each part over HTTPS or reads it from a folder the player chooses. It checks size and SHA-256 against pins compiled into the build. It extracts the parts into a staging folder with fail-closed zip-slip and size-cap checks, renames staging into `%LOCALAPPDATA%\UNDERTOW\ac\v1`, and writes `installed.json` last. Every failure path and both cancel paths are tested offline with fixture zips.

## Deviations from Plan

### Additions within scope (Rule 2, threat model T-02.2.2-11..17)

- `AutochartPaths.is_under_root(path)` backs the root-confined recursive remover and the file deletes.
- `PackExtractor` accepts a `progress_every` key in `limits` (tests only), so the cancel-mid-extract test gets a per-file progress hook.
- `PackInstaller.extract_limits` is a test seam that is passed through to the extractor.
- Part names in the spec must be a single safe path segment. Anything else is treated as not available.
- If a complete part from an earlier failed run is still in dl/, it is re-verified before use, and a stale one is downloaded fresh.

### Not exercised by tests

- The default HTTPRequest fetcher (stall timer, one retry, rename from .part) is not covered by unit tests, because they never touch the network. Plan 08/09 UI work or a manual run will exercise it.

## Known Stubs

- `PackSpec.PARTS` is empty on purpose. It is the generator's "no build" output, and plan 06's `pack_build.py` regenerates it with real pins. Until then the installer reports `not_available` with the D-10 text.
