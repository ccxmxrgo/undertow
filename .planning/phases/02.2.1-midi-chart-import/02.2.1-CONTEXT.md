# Phase 02.2.1: MIDI chart import - Context

**Gathered:** 2026-10-11 (orchestrator, from the user's request; no discuss session — decisions below are the user's or locked defaults)
**Status:** Ready for planning

<domain>
## Phase Boundary

Songs whose only chart is a Clone Hero / Guitar Hero `notes.mid` (typical for GH3 "Legends of Rock" rips and most
Clone Hero packs) import and play exactly like `.chart` songs. Today the scanner rejects them with
`SongEntry.ERR_MIDI` ("MIDI charts not supported yet", src/core/song_scanner.gd ~line 288). This phase removes that
error by adding a runtime `.mid` reader. Nothing about judging, timing, visuals or the song list UI changes.
Requirement CONT-01 (pulled forward from v2) plus the `.mid` half of SONG-07 (solo note 103).

</domain>

<decisions>
## Implementation Decisions

- **D-01 (user, 2026-10-11): add `.mid` support now**, as a small inserted phase before Offline Versus. Trigger: a
  friend downloaded a GH3 Legends of Rock pack and every song showed "MIDI charts not supported yet".
- **D-02 Reuse the existing pipeline.** The `.mid` reader produces the same `ParsedChart` (5-fret gems in ticks, tempo
  map, time signatures, events/sections, solos, resolution) that `ChartParser` produces from `.chart`, so
  `ChartImporter`'s existing 5-fret → 4-lane mapping (Green/Red/Yellow/Blue+Orange, open = lanes 2+3, same-tick merge,
  min sustain), fingerprinting, caching and song list behaviour apply unchanged. No second lane mapping.
- **D-03 Track choice:** `PART GUITAR` first; if absent, fall back in order to `T1 GEMS` (GH1/GH2-era name),
  `PART GUITAR COOP`, `PART RHYTHM`, `PART BASS`. Unknown tracks are ignored. If no usable track: a clear error
  ("This .mid has no guitar part") instead of the old one.
- **D-04 Difficulties:** Easy 60-64, Medium 72-76, Hard 84-88, Expert 96-100 (G R Y B O). Notes 65/77/89/101 (force
  HOPO on) and 66/78/90/102 (force strum) and 104 (tap) are modifiers only — no gems (same as `.chart` 5/6 flags).
  Open notes: support the common Clone Hero convention (ENHANCED_OPENS text event / SysEx open markers) only if cheap;
  otherwise ignore and note it. Sustains: note-off minus note-on; apply the same minimum-sustain rule ChartImporter
  already uses (Clone Hero treats sustains shorter than ~1/12 beat... follow the existing `.chart` threshold).
- **D-05 Tempo/meter:** tempo meta events (FF 51) on track 0 → tempo map; time signature (FF 58) → TS entries;
  resolution = header division (ticks per quarter). SMPTE division: reject with a clear error.
- **D-06 Sections:** `EVENTS` track text events `[section xxx]` / `[prc_xxx]` → section names, same cleanup as `.chart`
  sections (02.2-03 work). Solos: note 103 on the chosen instrument track → solo start/end (SONG-07).
- **D-07 Precedence:** if a folder has both `notes.chart` and `notes.mid`, keep using `.chart` (no behaviour change for
  existing songs). song.ini metadata, `delay`, preview time keep working for `.mid` songs exactly as for `.chart`.
- **D-08 Safety (untrusted files):** same hardening style as ChartParser: max file size (reuse/align `MAX_BYTES`),
  bounded track count/lengths, running status, variable-length quantities capped at 4 bytes, SysEx/meta skipped by
  length, truncated/corrupt files fail cleanly with an error, never hang or crash, never read past the buffer.
- **D-09 Parser choice:** write a small pure-GDScript MIDI reader (typed RefCounted, unit-testable) in src/core, or
  vendor brainfoolong/gdscript-midi-parser if research shows it is solid on real CH files and licence-compatible.
  Researcher decides; prefer own code if the vendored one needs heavy changes.
- **D-10 Test data:** no copyrighted charts in the repo. Tests build `.mid` bytes in code or use small self-authored
  fixture files (a generated minimal CH-style notes.mid with tempo changes, TS, sections, solos, all 4 difficulties).
- **D-11 Audio:** GH3/CH rips usually ship `song.ogg` + `guitar.ogg` (+ `rhythm.ogg`); the scanner's existing audio
  discovery/stem handling applies. If research finds `.opus`/`.mogg` audio is common in such packs and unsupported,
  report it with a clear per-song error (do not try to add an Opus decoder in this phase).
- **D-12 Timing core untouched:** conductor/clock_model/input_judge/hull_score at 72e21ce and judge_config at fbcf994;
  tools/check_timing_gate.ps1 must print TIMING GATE OK.
- **D-13 Friend build:** the phase ends with a v0.5.2 zip (tools/dist.ps1 version bump, README "WHAT'S NEW IN v0.5.2",
  tester checklist line: "drop a song folder with notes.mid into Songs, rescan, play it"), built in the cloud with the
  Linux engine + Windows templates, pck selftest BUNDLED_OK 20.
