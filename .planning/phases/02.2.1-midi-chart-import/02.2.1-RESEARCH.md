# Phase 02.2.1: MIDI chart import - Research

**Researched:** 2026-10-13
**Domain:** Standard MIDI File (SMF) parsing in pure GDScript + Clone Hero / Guitar Hero `.mid` chart conventions, plugged into the existing `.chart` import pipeline
**Confidence:** HIGH (codebase read in full on the touched paths; format facts cross-checked against the GuitarGame_ChartFormats docs and YARG.Core's MidReader source; tick->seconds precision measured with the real ChartImporter in Godot 4.7.2)

## Summary

This is a **rebuild**: v0.5.2 already shipped this feature but the source was lost. The current tree is v0.5.1 (`tools/dist.ps1` says `v0.5.1`, `SongEntry.ERR_MIDI` still exists, no MIDI code anywhere in `src/`). `.planning/reference/v0.5.3-README.txt` ("WHAT'S NEW IN v0.5.2" + SONGS) is the acceptance spec. Everything downstream of `ParsedChart` (lane mapping, sustain rule, seconds conversion, solos, sections, time signatures, fingerprint, cache, song list) already exists and must not change. The whole job is: one new byte reader that produces a `ParsedChart` from `notes.mid`, one dispatch helper so all four places that parse a chart file accept `.mid`, scanner/error/cache changes, and the v0.5.2 zip.

Write the MIDI reader yourself (D-09). The candidate vendor library `brainfoolong/gdscript-midi-parser` (MIT, 489 lines) has real bugs that matter for Clone Hero files: `++nbytes` is a no-op in GDScript, so its VLQ length cap never fires. `str_from_buffer` calls `slice(i, readBytes)` with the wrong end index. It resets running status after meta/SysEx events, but Phase Shift-authored charts depend on running status surviving them, and when that happens it silently returns "end of buffer". It does not handle `F7` escape SysEx. It is stateful and untyped, and it has an off-by-one in `get_bytes_rest`. Fixing all of that is more work than about 250 lines of typed, bounded code that follows the existing `ChartParser` hardening style.

The one non-obvious design point is **tempo precision**. MIDI tempo is microseconds per quarter note (uspqn), and `.chart` uses integer milli-BPM. I measured this in Godot 4.7.2 with the real `ChartImporter`. If uspqn is rounded to integer milli-BPM, a 575 s chart with 4 non-round tempos ends up **0.246 ms** off the exact time. If `60_000_000_000.0 / uspqn` is stored as a **float** in `ParsedChart.tempo[i].milli_bpm`, the error is **0.0 ms**. `ChartImporter._segments` already does `float(t["milli_bpm"]) / 1000.0`, so this needs **no importer change**. The "within 1 ms of .chart" promise is then provable with two tests. The first is fingerprint-identical parity between a generated `.mid` and an equivalent generated `.chart`. The second checks a long chart with non-round tempos against an independent analytic uspqn sum.

**Primary recommendation:** Add `SmfReader` (bytes -> bounded track/event lists), `MidiChartReader` (CH semantics -> `ParsedChart` with `EasySingle`..`ExpertSingle` tracks, float milli-BPM tempo, `section` events, `solo`/`soloend` events), and `ChartFile.parse(path)` (extension dispatch + size cap) used by the scanner, `SongLibrary.build_chart`, `SongSelect.parse_sections` and the playtest driver. Invalidate only cached entries that still carry the legacy "MIDI charts not supported yet" error. Do NOT bump `IMPORTER_VERSION`/`MAPPING_VERSION`: that would change every fingerprint and orphan every best score.

### Pattern 1: SmfReader (bounded SMF grammar)
**What:** Static `read(bytes: PackedByteArray, limits := {}) -> Dictionary`. It never asserts, never prints, and never indexes past `bytes.size()`.
**Rules (all `[CITED: GuitarGame_ChartFormats docs/Chart-File-Formats/mid-format/Technical-Details.md]` unless noted):**
- Header: `"MThd"`, a 4-byte BE length (honour it and skip extra header bytes), format (u16), ntracks (u16), division (u16). Fail with `"Unreadable .mid"` when: the file is shorter than 14 bytes, the magic is wrong, the length is < 6, **bit 15 of division is set (SMPTE, D-05)**, or division == 0. Format 2: fail. Format 0: allowed, but it naturally yields "No guitar part in .mid" because there is no named guitar track. The CH docs say only type 1 is supported. `[CITED: mid-format/Format-Overview.md "Type 0/2 and SMPTE resolution are not supported"]`
- Chunks: loop while `pos + 8 <= size`. Type `"MTrk"` is parsed. **Any other 4-char type is skipped by its length.** A chunk length that runs past EOF means fail `"Unreadable .mid"`. Do not trust `ntracks` (the docs say the actual count may differ). Cap the parsed tracks (e.g. `MAX_TRACKS := 256`). Skip any extras and add a warning.
- Delta time: VLQ, **max 4 bytes**. A 5th continuation byte is a fail. Absolute tick is a 64-bit int. If the tick goes > `ChartParser.MAX_TICK` (2147483647), fail (or stop the track with a warning, but be consistent).
- Running status: data byte (< 0x80) as the first byte reuses the last **channel** status. **Do NOT reset running status after meta/SysEx.** Clone Hero charts authored by Phase Shift rely on it continuing (`[CITED: Format-Overview.md "Notable Specification Violations"]`; NAudio breaks on this). A data byte with no prior channel status: fail the file.
- Channel events: `8n`/`9n`/`An`/`Bn`/`En` take 2 data bytes, `Cn`/`Dn` take 1. Only keep note on/off (`9n` vel 0 == off). Skip the others by size.
- `F0 <vlq len> <bytes>` and `F7 <vlq len> <bytes>`: skip by length, but keep a copy of the payload when the length is 8 (`F0` form: `'P' 'S' 0x00 type diff mod value F7`), so Phase Shift open-note SysEx can be read. The payload may contain 0xFF bytes, so never scan for `F7`. Always use the length. `[CITED: Format-Overview.md]`
- `FF <type> <vlq len> <data>`: skip by length. Keep `0x03` (track name), `0x01`-`0x0F` text, `0x51` (tempo, needs len >= 3), `0x58` (TS, needs len >= 2), and `0x2F` (end of track, which stops the track). A missing End-of-Track is tolerated.
- Status bytes 0xF1-0xF6/0xF8-0xFE inside a track: fail (they are not valid in SMF).
- Track name = text of the **first `FF 03` at tick 0** in the track, `strip_edges()`. Matching is case-insensitive via `to_upper()`. `[VERIFIED: YARG.Core MidReader.GetRecognizedTrackName loops tick-0 events for the first track name]`
- **Memory:** do not turn every event of every track into a Dictionary. Store per track only what CH needs: notes as packed ints or small dicts, text events, tempo/TS (track 0), and PS SysEx. Better still, read each track's name first, then **skip unrecognised tracks entirely by chunk length** (VENUE/vocals/drums/animation tracks can be large).

### Pattern 2: Note pairing (MIDI note -> gem with length)
- Pair by pitch only (ignore channel and velocity).
- Within one tick, process **note-offs before note-ons** (stable by file order otherwise). This makes back-to-back same-pitch notes work regardless of whether the authoring tool wrote `on@480, off@480` or `off@480, on@480`.
- A note-on while the same pitch is open: close the open note at this tick, then open the new one.
- A note-off with no open note: ignore it (count a warning).
- Still open at end of track: length 0.
- Gems are emitted at close time, so they come out of order. **Sort each difficulty track by (tick, seq)** before handing it to `ChartImporter`. `_collect` groups chords by consecutive equal ticks, which needs sorted input.

### Pattern 3: CH semantics -> ParsedChart contract
`ChartImporter` only reads these fields `[VERIFIED: src/core/chart_importer.gd]`:
- `parsed.ok`, `parsed.resolution` (header division, clamp 1..65535), `parsed.song` (leave `{}`; .mid has no metadata and song.ini supplies it. Do NOT copy the track-0 name, which is often junk like "midi_export"), `parsed.warnings`.
- `parsed.tempo`: `[{tick, milli_bpm, seq}]` from **track 0 only**. `[VERIFIED: YARG.Core MidReader "The sync track is the very first track in the file"]` Use `milli_bpm = 60_000_000_000.0 / float(uspqn)` (**float**). Skip `uspqn == 0` (division by zero). The importer clamps BPM to 1..2000 and adds 120 BPM at tick 0 if missing.
- `parsed.time_sigs`: `[{tick, num, exp, seq}]` from FF 58 on track 0 (`num` = byte 0, `exp` = byte 1). The importer clamps num to 1..32 and exp to 0..5.
- `parsed.events`: `[{tick, text, seq}]`. From the `EVENTS` track text events, normalize to the `.chart` form so `ChartImporter._sections` works unchanged:
  1. strip whitespace, then strip one leading `[` and one trailing `]`;
  2. case-insensitive match `^(section|prc)[ _](.*)$` `[VERIFIED: YARG.Core TextEvents.TryParseSectionEvent, "(?:section|prc)[ _](.*)"; CITED: Global-Events.md "some ... may have an underscore instead of a space"]`;
  3. emit `"section " + name`. Recommended (discretion): when the name came from `prc_` or contains `_` and no space, replace `_` with a space (`prc_verse_1` -> "verse 1"). Other events (`[end]`, `[music_start]`, `[coda]`) can be stored verbatim or dropped. `_sections` ignores them either way.
- `parsed.tracks["EasySingle"|"MediumSingle"|"HardSingle"|"ExpertSingle"]`: `[{tick, type:"N"|"E", a, b, text, seq}]`:
  - Pitch base per difficulty: Easy 60, Medium 72, Hard 84, Expert 96. Offsets 0..4 -> `a = 0..4` (G R Y B O), `b = len_ticks` after the cutoff (below). `[CITED: mid-format/Tracks/5-Fret-Guitar.md]`
  - Offsets 5/6 (force HOPO/strum), 104 (tap), 105/106 (versus), 116 (SP), 120-127: **no gem** (D-04).
  - **Open notes (cheap, recommended):** (a) if the track has a text event `ENHANCED_OPENS` (with or without brackets), then pitches 59/71/83/95 become `a = 7`. Without that event, ignore 59/71/83/95 (they are GH2/RB animation notes). (b) Phase Shift SysEx payload `50 53 00 00 <diff 0..3> 01 <1=start/0=end>`: gems of that difficulty whose tick is in `[start, end)` become `a = 7` (open markers do not include their end tick). `[CITED: Format-Overview.md PS SysEx spec + "open note markers ... do not affect the tick they end on"; 5-Fret-Guitar.md]` The existing mapping turns `a = 7` into lanes 2+3. GH3 rips contain no opens (GH3 had none), so (b) can be cut if time is short. Note it in SUMMARY if cut.
  - **Solos (SONG-07):** note 103 on/off on the chosen track. Append `{type:"E", text:"solo", tick:on}` and `{type:"E", text:"soloend", tick:max(on, off-1)}` to **all four** difficulty tracks. `ChartImporter._solos` reads `E` entries per difficulty track, pairs solo/soloend, and counts notes with `time in [start, end]` (inclusive). The `off-1` keeps the MIDI phrase end exclusive, matching Moonscraper's historical `SOLO_END_CORRECTION_OFFSET = -1` `[VERIFIED: constant present in YARG.Core MidReader.cs]`.
  - **GH1/2 compatibility (recommended):** if the chosen track has **no note 116 at all**, treat 103 as Star Power and emit no solos. `[CITED: 5-Fret-Guitar.md "solo markers should be treated as Star Power if there aren't any modern Star Power phrases placed on note 116"]` This needs only file data (no song.ini), so scan and play stay deterministic. The ini override `multiplier_note`/`star_power_note` is optional and not recommended (it would need ini plumbing into every `ChartFile.parse` caller).
- **Sustain cutoff (.mid only):** `len < resolution / 3` (integer division) -> `b = 0`. This is Clone Hero/YARG's .mid default ("sustains shorter than a 1/12th step are cut off"). `[VERIFIED: YARG.Core MidReader: SustainCutoffThreshold default = song.resolution / 3, applied as sus < threshold -> 0; CITED: 5-Fret-Guitar.md]` After that, `ChartImporter`'s own rule (`len*4 <= res` -> tap) applies unchanged. This is why the D-04 instruction "follow the existing .chart threshold" is not enough on its own. Without the cutoff, a 480-res GH3 rip whose plain notes are 121..159 ticks long would become sustains in UNDERTOW, while Clone Hero shows them as taps. The cutoff runs in the reader, so D-02 (no second lane mapping, importer unchanged) holds. Do not read `sustain_cutoff_threshold` from song.ini (same determinism reason as above). Optional and not recommended.
- **Track choice (D-03 + README):** candidates in order `PART GUITAR`, `T1 GEMS`, `PART GUITAR COOP`, `PART RHYTHM`, `PART BASS`. Pick the **first candidate that yields >= 1 gem in any difficulty** (a present but empty `PART GUITAR` falls through). Take the **whole track**; never mix difficulties from different tracks. If more than one track has the same name, use the first. If nothing qualifies, `ok = false`, `error = "No guitar part in .mid"`. Never pick `PART GUITAR GHL`, `PART KEYS`, drums or vocals.

### Pattern 4: Errors and caps
| Condition | Result |
|-----------|--------|
| file > cap | `"Chart too large"` (existing `SongEntry.ERR_TOO_LARGE`; scanner already checks `_file_len` vs `ChartParser.MAX_BYTES`). ### Pattern 5: One dispatch point (`ChartFile`)
Four call sites parse chart files today `[VERIFIED: grep]`:
1. `src/core/song_scanner.gd:294-297` (scan)
2. `src/autoload/song_library.gd:209` `build_chart` (re-parses, then checks `fingerprint == stored`)

### Pattern 6: Scanner, precedence, cache
- `_pick_chart(files)`: keep the existing `.chart` preference logic exactly. Only if there is no `.chart`: return `notes.mid` (case-insensitive) or else the first `.mid` by sorted name. `.midi` is ignored (CH does not support it `[CITED: Format-Overview.md]`). Then delete the `if has_mid: return _fail(e, SongEntry.ERR_MIDI)` branch. `_discover` and `_import_candidate` already treat `.mid` as a chart and `folder_signature` already includes `.mid` files `[VERIFIED]`. `ZipExtractor.ALLOWED_EXTS` already includes `mid` `[VERIFIED]`, so no `EXTRACT_VERSION` bump is needed.
- Metadata: for `.mid`, `parsed.song` is empty, so the existing code falls back to song.ini and then the folder name. `delay`, `preview_start_time`, `charter`/`frets` keep working with no change `[VERIFIED: import_folder]`.
- **Cache invalidation (README: "Songs that showed 'MIDI charts not supported yet' are read again automatically on the first scan"):** treat a cached entry whose `error == "MIDI charts not supported yet"` as a miss, in `SongScanner._cached` (or `SongCache.lookup`). ### Pattern 7: Proving ".mid timed exactly like .chart (within 1 ms)"
Two complementary gdUnit tests (`tests/test_midi_parity.gd`):
1. **Pipeline parity (fingerprint-identical).** Generate one deterministic song description in code: resolution 480, tempos whose uspqn map to **exact** integer milli-BPM (500000->120000, 600000->100000, 400000->150000, 468750->128000, 375000->160000), TS changes, sections, 1-2 solos, all 4 difficulties with chords, open notes, orange, sustains >= res/3 and plain notes. Emit it twice: as `.chart` text (`ChartParser`) and as SMF bytes (`MidiWriter` -> `MidiChartReader`). Notes shorter than `res/3` are written with length 0 in the `.chart` and with their short length in the `.mid`. For each difficulty and a non-zero delay (e.g. `delay_ms = 137`): `ChartImporter.build` both. Assert equal note count; per note the same lane, `absf(dt) < 0.001` and `absf(ddur) < 0.001`; equal sections, solos (start/end/note_count), time_sigs, tempo_map. Finally assert **`ChartImporter.fingerprint` strings are identical**, which is the strongest statement (ms-rounded identity of every note).
2. **Absolute precision vs an independent oracle.** A ~10-minute `.mid` with **non-round** tempos (461538, 428571, 333333 uspqn, which have no exact milli-BPM). Compute the expected seconds of each note with a separate integer-first formula, `sum(delta_ticks * uspqn) / (res * 1e6)`, without using `ChartImporter`, and assert `< 0.001 s` (expect ~1e-9). Probe result for reference, 575 s chart with 4 tempos: float path error 0.000 ms, integer-milli-BPM path 0.246 ms `[VERIFIED: Godot 4.7.2 probe in this session using the real ChartImporter]`.
3. **Song-level parity (scanner).** Make two fixture folders with the same generated audio (`SongFixture.make_wav`), one with `notes.chart` and one with `notes.mid`. Scan both and assert `difficulties[*].note_count` are equal and the fingerprints are equal. Then `SongLibrary.build_chart`-equivalent (`ChartFile.parse` + `build` + `fingerprint`) succeeds for the `.mid` entry (catches a forgotten call site).

### Anti-Patterns to Avoid
- **Rounding uspqn to integer milli-BPM:** drift (measured 0.25 ms over ~10 min with 4 tempos; grows with odd tempos). Store a float.
- **Mixing difficulties across tracks** (Expert from PART GUITAR, Easy from PART BASS): not what CH does, and it surprises players.
- **A second lane mapping in the MIDI reader** (D-02): the reader outputs 5-fret `a` values (0-4, 7). Lanes belong to `ChartImporter`.
- **Reading song.ini inside the reader:** the scan path and the play path must produce identical charts (fingerprint check). Keep the reader bytes-in, chart-out.
- **Scanning SysEx for `F7`:** CH SysEx payloads may contain 0xFF. Always skip by length.
- **Resetting running status after meta/SysEx:** breaks real Phase Shift-era charts.

## Common Pitfalls

### Pitfall 1: Out-of-bounds `PackedByteArray` reads
**What goes wrong:** In GDScript, indexing past the end raises a script error (debug) and does not return a sentinel. A truncated file then becomes an engine error spam or an aborted scan instead of a clean "Unreadable .mid".
**How to avoid:** Have one `_need(n)` check before every read, and make all reads go through helpers that check `pos + n <= end` (where `end` is the current chunk end, not the file end).
**Warning signs:** "Out of bounds get index" in the test output. Use a truncation sweep test: for every prefix length of a valid file, `parse` returns (ok or error) and the log stays clean.

### Pitfall 2: Running status across meta/SysEx
**What goes wrong:** Strict parsers reset running status after `FF`/`F0`, so real Phase Shift-era charts fail or lose notes. `[CITED: Format-Overview.md]`
**How to avoid:** Only channel events set running status. Meta/SysEx leave it alone. Add a test: running status continuing after an `FF 01` text event.

### Pitfall 3: Sustain cutoff mismatch (.mid shows sustains Clone Hero hides)
**What goes wrong:** MIDI notes always have a length. Without the CH `.mid` cutoff (`len < res/3` -> 0), many plain notes in DAW/GH3 conversions become short sustains.
**How to avoid:** Apply the cutoff in the reader (Pattern 3). Test at res 480: lengths 120, 159, 160, 161. Expected: 0, 0, sustain, sustain at the ParsedChart level. Then importer behaviour: 160 at res 480 is `160*4 = 640 > 480`, so it is a sustain.

### Pitfall 4: Out-of-order gems
**What goes wrong:** Gems are produced at note-off time. Unsorted tracks break `_collect`'s chord grouping (same-tick merge) and produce duplicate or merged-wrong notes.
**How to avoid:** Stable sort each difficulty track by (tick, seq) after building it.

### Pitfall 5: Back-to-back same-pitch notes
**What goes wrong:** `on@480` written before `off@480` closes the new note immediately (length 0) and leaves the real off orphaned.
**How to avoid:** Offs before ons within a tick (Pattern 2). Test both byte orders and expect identical output.

### Pitfall 6: A forgotten call site
**What goes wrong:** The scan succeeds, but `SongLibrary.build_chart` still calls `ChartParser`. The `.mid` song then shows as playable and fails on Dive with "Unreadable .chart (line 1)", or Song Select shows no sections.
**How to avoid:** `ChartFile.parse` everywhere. Add a test that greps-by-behaviour: build the chart for a `.mid` entry through `SongLibrary.build_chart` (or the same code path) and assert `chart.id == entry fingerprint`. A grep check in verification: `grep -rn "ChartParser.parse_bytes(" src/ tools/playtest` only hits `chart_file.gd` (the `tools/autochart` dev tool may keep it).

### Pitfall 7: 103 as Star Power in GH1/GH2-era charts
**What goes wrong:** `T1 GEMS` / GH2 charts use 103 for Star Power, so every SP phrase would become a "solo" (wrong `has_solos`, a wrong Phase 3 Solo Duel later).
**How to avoid:** No 116 on the chosen track means no solos from 103 (Pattern 3). `[CITED: 5-Fret-Guitar.md]` Test: a track with 103 and no 116 gives `solos == []`, and with one 116 present it gives solos.

### Pitfall 8: uspqn = 0 or absurd tempos
**What goes wrong:** Division by zero gives inf/NaN milli-BPM.
**How to avoid:** Skip `uspqn <= 0` with a warning. The importer clamps to 1..2000 BPM. Note: `ChartImporter.build` already drops non-finite note times.

### Pitfall 9: Invalid UTF-8 in text events
**What goes wrong:** `get_string_from_utf8()` on Latin-1 bytes logs "Unicode parsing error" lines (I observed such lines from engine startup in a headless run). That is noisy, not fatal.
**How to avoid:** For text events, use `get_string_from_ascii()` when all bytes are < 0x80. Otherwise use UTF-8. Cap the text length read (e.g. 256 bytes for names; skip the rest by length).

### Pitfall 10: Unbounded work on hostile files
**What goes wrong:** A 64 MB file of tiny events gives millions of Dictionaries (memory) and seconds of GDScript looping on the scan worker.
**How to avoid:** A smaller `.mid` byte cap (16 MB recommended). Skip unrecognised tracks by chunk length without parsing their events. Cap gems per difficulty (300000) and text events (reuse `ChartParser.MAX_ENTRIES` / `ChartImporter.MAX_SECTIONS` downstream).

### Pitfall 11: Losing the work again
**What goes wrong:** The v0.5.2 code was lost because it was never pushed.
**How to avoid:** Each plan ends with commit + `git push` (origin `github.com/ccxmxrgo/undertow`). Also commit `.planning/reference/` (currently untracked).

## Code Examples

### VLQ with a 4-byte cap and bounds (pattern for SmfReader)
```gdscript
# Source: SMF spec as documented in GuitarGame_ChartFormats Technical-Details.md (VLQ max 4 bytes, max 0x0FFFFFFF)
## Returns the value, or -1 on overrun / > 4 bytes. `st` = {pos:int, end:int} cursor.
static func _vlq(b: PackedByteArray, st: Dictionary) -> int:
	var v := 0
	for i in 4:
		if st.pos >= st.end:
			return -1
		var c: int = b[st.pos]
		st.pos += 1
		v = (v << 7) | (c & 0x7F)
		if c & 0x80 == 0:
			return v
	return -1  # a 5th continuation byte: unreadable
```
(Typed cursor fields or a small inner class are preferable to a Dictionary for speed. This is shape only.)

### Big-endian reads
```gdscript
static func _u16(b: PackedByteArray, p: int) -> int:
	return (int(b[p]) << 8) | int(b[p + 1])

static func _u32(b: PackedByteArray, p: int) -> int:
	return (int(b[p]) << 24) | (int(b[p + 1]) << 16) | (int(b[p + 2]) << 8) | int(b[p + 3])
# tempo: uspqn = (b[p] << 16) | (b[p+1] << 8) | b[p+2]   (FF 51 03)
# milli_bpm = 60000000000.0 / float(uspqn)   -> float, exact through ChartImporter._segments
```

### Section normalization
```gdscript
# Source: YARG.Core TextEvents.TryParseSectionEvent "(?:section|prc)[ _](.*)" + ChartImporter._sections expecting "section <name>"
static func _section_text(raw: String) -> String:
	var t := raw.strip_edges()
	if t.begins_with("["): t = t.substr(1)
	if t.ends_with("]"): t = t.substr(0, t.length() - 1)
	var low := t.to_lower()
	var name := ""
	if low.begins_with("section") and t.length() > 7 and (t[7] == " " or t[7] == "_"):
		name = t.substr(8)
	elif low.begins_with("prc") and t.length() > 3 and (t[3] == " " or t[3] == "_"):
		name = t.substr(4)
	else:
		return ""  # not a section
	if not name.contains(" "):
		name = name.replace("_", " ")
	return "section " + name.strip_edges()
```

### Applicable ASVS Categories (Level 1)

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | no | — |
| V3 Session Management | no | — |
| V4 Access Control | no | — |

### Known Threat Patterns for a GDScript binary parser on untrusted files

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Truncated / lying chunk lengths -> out-of-bounds reads | Tampering / DoS | Chunk-end cursor, `_need(n)` before every read, fail "Unreadable .mid" |
| Huge VLQ / meta / SysEx lengths | DoS | VLQ 4-byte cap; skip by length only after checking `pos + len <= chunk_end` |
| Event floods (millions of tiny events) | DoS (memory/CPU on the scan worker) | 16 MB `.mid` cap; skip unrecognised tracks unparsed; per-difficulty gem cap 300000; downstream section/TS caps |
| Infinite loop on zero-advance | DoS | Every loop iteration must advance `pos` (assert in tests via a truncation sweep + random-byte fuzz with a fixed seed and a time budget) |
| Division by zero / NaN tempo | Tampering | Skip `uspqn <= 0`; importer clamps BPM and drops non-finite times |
| Hostile text (control chars, huge names) | Tampering (UI) | `ChartImporter._clean_section_name` (existing), text read cap |
| Poisoned scan cache JSON | Tampering | Existing `SongEntry.from_dict` validation; the new error strings fit `MAX_STR` |
