## Summary

Recommendation: build the board as **2D `_draw` with a pure projection class**, not Godot 3D. The sketch is already a 2D canvas projection (`P.c`); the whole look is polylines, outline shapes, text and radial fades, all of which Godot's CanvasItem API does directly and batches well on the Compatibility (GL) renderer. 3D would add a Camera3D, SubViewport/compositing with the 2D HUD, 3D-to-screen math for every label, and make screenshot/pixel asserts and headless unit tests harder, for no readability gain. All timing-relevant math lives in a new static `Trench` (RefCounted) with no node dependencies, so the D-04 invariant is unit-testable headless.

The timing core stays untouched. The intro runs **before `Conductor.begin()`** on the wall clock (it is pure presentation); the 3-2-1 count-in is just the conductor lead-in raised from 2 to 3 beats (`Gameplay.LEAD_IN_BEATS`), rendered from `song_time()` (which is negative during lead-in). So clock tests (`test_clock_*`, `test_pause_resume`) are unaffected. The only gameplay-side hazards are (a) `Gameplay._process` calling `Autoplay.update(0.0)`/`judge.tick(0.0)` while the intro plays and the conductor is not yet started (gate it), and (b) the harness/tests assume a begun conductor right after `Gameplay` loads.

The 01.1-06 visor is removed wholesale (3 scripts, 1 shader, `test_visor.gd`, polish-harness visor sections, Gameplay glitch wiring). Only `VisorHud.beat_phase` is worth keeping (move to a shared pure helper; its 3 asserts move with it). `progress_for`/`timecode`/timeline math are not needed by the minimal HUD and should be deleted with their tests.

**Primary recommendation:** Rewrite `Highway` internals as the projected cable board (keep the class name, `setup/on_judged/on_lane_pressed/on_sustain_end/_state/S_*` API so Gameplay wiring and harness keep working), add a `Trench` projection class, an `Arena` background node, and a `GogglesIntro` overlay driven by a pure `IntroTimeline`; build the run immediately but call `conductor.begin()` only when the intro reaches the count-in.

### Projection and depth mapping (Focus Q2)

Port of `P.c`, scaled from the 1600x900 sketch to 1920x1080 (exact factor 1.2). All values are starting points to tune from screenshots.

Sketch (verbatim):
```
persp(d): z = d*10; s = 1/(1+z*0.42); smin = 1/(1+10*0.42); n = (s - smin)/(1 - smin)
P.c(f, d): sag = sin(d*PI)*18*(1-d)
           x = vp.x + f*175*s*(0.35 + 0.65*n)
           y = vp.y + (hitY - vp.y)*n + sag - f*f*30*n*n
```
Scaled constants: `VP = (960, 396)`, `HIT_Y = 960`, `LANE_SPREAD = 210`, `SAG = 21.6`, `RING_CURVE = 36`, lane unit `f = lane - 1.5`, hit-ring arc spans `f in [-2.1, 2.1]`. Screen size in sketch: note radius `r = 30*s + 4` -> `36*s + 5` at 1080p.

Key properties (verified algebraically from the formulas):
- `d = 0`: `z = 0 -> s = 1 -> n = 1`; `sag = sin(0) = 0`; so `x = 960 + f*210`, `y = 960 - 36*f*f`. The hit point is lane-specific (curved ring): outer lanes (f = +-1.5) sit at y = 879, inner (f = +-0.5) at y = 951. The invariant is "note centre == `Trench.hit_point(lane)` at `note.time == vt`", NOT a single y.
- `d = 1`: `s = smin = 0.1923`, `n = 0`, `sag = 0`; so all cables converge to `x = 960 + f*210*0.1923*0.35 = 960 + f*14.1`, `y = 396` (not exactly one point: a tiny fan, as in the sketch).
- `d` MUST be linear in time and nothing else: `d = (note_time - vt) / approach` with `vt = song_time + Settings.visual_offset` (identical to current `Highway._draw`, where `y = HULL_Y - (time - vt)*pps`, so the visual offset semantics are unchanged; judgment still uses raw `song_time`).
- Singularity: `s = 1/(1 + 4.2d)` blows up at `d = -0.238`. Clamp projected `d` to `>= -0.15` (or keep missed notes frozen on the ring as the sketch does with `Math.max(d, 0)`), and skip drawing beyond `d > 1`.
- On-screen speed is NOT constant. Near the ring `dn/dd = -4.2/(1 - smin) = -5.2`, so screen speed at the hit ring is `(960-396)*5.2/approach = 2933/approach` px/s vs the old uniform 700 px/s. At approach 1.5 s that is ~1950 px/s at the ring, slowing toward the horizon. The Perfect (+-35 ms) window spans about +-68 px of travel at the ring, Good (+-70 ms) about +-136 px. Treat this as the main feel risk and tune `APPROACH_BASE` visually.
- Scroll speed maps to approach: `approach = APPROACH_BASE / Settings.scroll_speed`. Recommend `APPROACH_BASE = 1.5 s` (0.5x -> 3.0 s, 1x -> 1.5 s, 3x -> 0.5 s); old visible span was `880/700 = 1.26 s`. Lookup at 1.5 s (time ahead -> d -> y on f=0 line, computed from the formula): 0.1 s -> 0.067 -> ~807; 0.3 s -> 0.2 -> ~641; 0.75 s -> 0.5 -> ~487; 1.5 s -> 1.0 -> 396. Notes 1 beat apart at 120 bpm (0.5 s) are ~100 px apart around the middle: readable. Expose it as a `const` plus `Trench.approach_for(scroll_speed)`. [ASSUMED: exact 1.5 s needs a playtest eyeball; the harness shots at 0.5x, 1x, 3x will check.]

Sustains: draw a ribbon between `d_head` and `d_tail = (time + duration - vt)/approach` along the cable (sample ~8-12 points per sustain, clamp tail to 1.0, head to >= 0 while holding, same as the old "consumed below the hull line" rule).

### Pattern 1: Pure projection class (testable)
```gdscript
class_name Trench
extends RefCounted
const VP := Vector2(960.0, 396.0)
const HIT_Y := 960.0
const LANE_SPREAD := 210.0
const APPROACH_BASE := 1.5
const Z_SCALE := 0.42
const D_MIN := -0.15          # never project past the singularity at -0.238

static func lane_f(lane: int) -> float: return lane - 1.5
static func approach_for(scroll_speed: float) -> float: return APPROACH_BASE / maxf(scroll_speed, 0.1)
static func depth_for(note_time: float, vt: float, approach: float) -> float:
	return (note_time - vt) / approach                      # LINEAR in time (D-04)
static func persp(d: float) -> Vector2:                     # returns (s, n)
	var s := 1.0 / (1.0 + clampf(d, D_MIN, 1.0) * 10.0 * Z_SCALE)
	var smin := 1.0 / (1.0 + 10.0 * Z_SCALE)
	return Vector2(s, (s - smin) / (1.0 - smin))
static func project(f: float, d: float) -> Dictionary:     # {pos, s, n}
	var sn := persp(d); var dd := clampf(d, D_MIN, 1.0)
	var sag := sin(dd * PI) * 21.6 * (1.0 - dd)
	var x := VP.x + f * LANE_SPREAD * sn.x * (0.35 + 0.65 * sn.y)
	var y := VP.y + (HIT_Y - VP.y) * sn.y + sag - f * f * 36.0 * sn.y * sn.y
	return {"pos": Vector2(x, y), "s": sn.x, "n": sn.y}
static func hit_point(lane: int) -> Vector2: return project(lane_f(lane), 0.0)["pos"]
```
Note: for `d < 0` the sag term `sin(dd*PI)` goes negative while `(1-dd) > 1`; harmless for the short missed-note tail but test it (see pitfalls).

### Pattern 4: Intro as pure timeline + overlay
Sketch 002 variant A table (seconds): goggles 0-1.1, black 1.1-1.25, CRT 1.25-1.65, arena fade 1.65-2.6, count 2.6-4.1 (3 beats at 0.5 s), end 4.1. Quick (variant b): black 0-0.05, CRT 0.05-0.4, arena 0.4-0.6, count 0.6-1.1.

Important: the sketch counts "3-2-1" on a fixed 0.5 s beat. In the game the beat is the CHART bpm (`60/bpm`), so the count-in phase length is `3*spb` (1.5 s at 120 bpm; 1.0 s at 180). Pre-count phases (room to arena fade) are fixed wall-clock seconds (about 2.6 s, may trim to 2.4 within the +-0.5 s discretion). Total therefore ~4 s at 120 bpm but varies by chart BPM; acceptable.

`IntroTimeline` (RefCounted, no nodes) API suggestion:
```gdscript
enum Mode { FULL, QUICK, NONE }
enum Phase { ROOM_GOGGLES, BLACK, CRT, ARENA, COUNT, DONE }
static func pre_count_seconds(mode: Mode) -> float      # FULL 2.6, QUICK 0.6, NONE 0
static func phase_at(t: float, mode: Mode) -> Dictionary # {phase, progress 0..1}
static func count_number(song_time: float, spb: float, beats: int) -> int  # 3,2,1 by ceil(-st/spb); 0 when st>=0
```
Count numerals must change exactly on beats of the lead-in clock: with `song_time` running from `-3*spb`, the "3" shows for `st in [-3spb, -2spb)`, "2" for `[-2spb, -spb)`, "1" for `[-spb, 0)`, "DIVE" at `st >= 0` for ~0.6 s. Because it derives from `song_time`, it is correct after a hitch, skip, or different bpm automatically.

### Intro integration with Conductor (Focus Q3)
1. `Gameplay.start(chart, autoplay, intro: IntroTimeline.Mode = FULL)`. Everything is built as today (so `g.judge`, `g.score`, `g.hud`, `g.highway`, `g.conductor` all exist immediately, preserving harness/test references), but `conductor.begin()` is NOT called in `start()`. Add `_began: bool`, `_intro_t0_ticks`.
2. `LEAD_IN_BEATS := 3` (was 2). The audio-start scheduling in `Conductor._start` already handles any lead-in (`_play_at = start_pos - time_delay - audio_offset`, starts immediately if `_play_at <= song_time`), so a short quick-mode lead-in is safe. Use `lead_in = beats * 60/bpm` with `beats = 3` for FULL, `1` for QUICK ("single count"), `3` for Space-skip ("short count-in" = skip straight to the count).

### Pitfalls and anti-patterns
- **Do not draw notes in time order.** Far-to-near only, else far notes overdraw near ones.
- **Do not let the depth be nonlinear.** Any easing on `d` breaks D-04. Easing only in `persp`.
- **Never clamp `d` to `[0,1]` before the ring crossing test.** Clamp only for drawing. A test at `d == 0` must give exactly `hit_point`.
- **Singularity at `d = -0.238`:** clamp to `D_MIN`; missed notes should fade out by `d ~ -0.15`.
- **Do not run judge/autoplay before the clock is started** (see integration step 3).
- **`_draw` allocations:** `Dictionary` returns from `Trench.project` are fine for tests; in the hot draw path use a variant that writes into reused locals/arrays (e.g. `project_into(f, d) -> Vector2` plus `scale_at(d) -> float`) to avoid ~100 dictionaries per frame. [ASSUMED: matters little at this note count, but the old code explicitly avoided per-frame allocations.]
- **Glow:** Canvas has no `shadowBlur`. Fake with 2-3 widening low-alpha strokes; keep "ready" notes distinguishable by brightness + outline, not glow alone (colour-independence rule from 1.1: shape + text always accompany colour).
- **Lane-number labels (1-4)** must come from `Settings.bindings.display_name` as the old Highway did (rebindable keys), drawn under each receptor.
- **Missed-note X marker and ghost alpha** (old: lane colour at 25%, destructive X) must be kept for non-colour feedback.
- **Fail squash:** `_fail_tween` scales `highway`/`feedback` about a pivot; with a perspective board the pivot should be `(960, HIT_Y)`; also fade `arena` or leave it (design call).
- **Input during intro:** `LaneInput.enabled=false` until count-in begins; otherwise key mashing during the intro registers strays and `HullScore` could take damage before the song.
- **Stretch:** the project uses `canvas_items` stretch with a fixed 1920x1080 design size; do all Arena coordinates in that space (never `get_viewport_rect()`), as the old code does.

## Common Pitfalls

### Pitfall 1: Hit ring is curved, so "crossing y" differs per lane
**What goes wrong:** test or harness asserts a note at `y == 960`; outer lanes cross at y~879.
**How to avoid:** compare against `Trench.hit_point(lane)`; harness reads that.
**Warning signs:** autoplay screenshot shows notes visibly past/before receptors on outer lanes.

### Pitfall 2: Perception of timing from non-uniform screen speed
**What goes wrong:** notes appear to accelerate near the ring, making the Good window feel wider/narrower than before.
**How to avoid:** tune `APPROACH_BASE`; keep depth linear; verify in 0.5x/1x/3x screenshots and a human pass. Do not "fix" feel by changing judge windows.

### Pitfall 3: Intro makes every existing scene test slow or wrong
**What goes wrong:** `test_gameplay_smoke` and harness `start_dive_from_menu` time out or read `song_time == 0`.
**How to avoid:** `Gameplay.pending_intro` (NONE in tests); in the harness, after the menu start, `await wait_until(func(): return g.is_began())` or press Space; update every scenario that waits on `song_time` to tolerate the pre-count seconds (add `Gameplay.is_began()`).

### Pitfall 4: Autoplay/judge ticking before begin
See integration step 3.

### Pitfall 5: Missing `queue_free` of intro on restart
`start()` frees `_run_root`; the intro is a child of `_run_root`, so restart is clean. Do not parent the intro to `Gameplay` directly. Skip input handlers must be removed with it (use `_unhandled_input` on the intro node itself, not a global autoload).

### Pitfall 6: Leftover `.godot` import cache for deleted shader
Run `--import` after deletions or exports can warn/fail.

### Count-in
```gdscript
static func count_number(song_time: float, spb: float, beats: int) -> int:
	if song_time >= 0.0 or song_time < -float(beats) * spb: return 0
	return clampi(int(ceil(-song_time / spb - 1e-9)), 1, beats)   # 3 for [-3spb,-2spb)
```
