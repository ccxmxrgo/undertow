### WR-05 per-frame debounce

- A single miss reaches `_arena_miss` twice in the same process frame: once from `judged`, once from `hull_changed`. The second call is dropped, so energy gets x0.4 once.
- `_arena_miss_frame` is reset to -1 in `start()`, so a restart cannot be silenced by a stale frame number from the previous run. `Engine.get_process_frames()` is monotonic, so there is no wrap or reuse risk.
- Side effect: two distinct misses in the same frame (a chord of two notes expiring together) now also count once. This is arguably better than before (x0.4 instead of x0.0256) and matches the visual intent. I do not treat it as a defect.
- A stray press handled in `_input` earlier in the same frame as a miss detected in `_process` also collapses to a single reaction. That is benign.
- The `is_instance_valid(arena)` guard also covers use after teardown.

### WR-06 lead-in clamp versus count numerals

- `Gameplay._begin_count_in` passes `lead_in_seconds(beats, bpm)` to the conductor.
- `GogglesIntro.on_count_started` sets `_spb = count_beat_seconds(beats, bpm)`, which is `lead / beats`.
- Every numeral computation is therefore in step with the real lead-in: `count_number`, `beat_fraction`, `ct = st + beats * _spb` (which is 0 at song_time = -lead), the HUD fade and the `bright` ramp. `beats * _spb` equals the clamped lead exactly.
- `_spb` is overwritten only on `on_count_started`. Before that, the PRE state never reads `_spb`, so there is no stale-value path.
- Skipped intros use beats = 3, and both sides compute from the same `_beats`, so they agree.
- The unclamped `seconds_per_beat` still drives `_spb` in `setup()`, but that value is never used before `on_count_started` overwrites it.
- Residual behavioural note: the QUICK single-beat numeral is now 0.6 s at 120 bpm and above. The test was updated to match.

I found no new bugs introduced by the fix diff. The remaining items are all Info.

## Info

### IN-01: Hull arc dips into the outer 32 px bottom margin

**File:** `src/ui/hud.gd:13-14, 221`
**Issue:** With `ARC_CENTER=(960,450)`, `ARC_RADIUS=612` and angles 1.114-2.028 rad, the arc's lowest point (~pi/2) is at y = 1062. That is inside the bottom 32 px (>= 1048), which contradicts the class doc "Nothing persistent in the outer 32 px" and D-06 clean edges.
**Fix:** Lower the radius or move the centre up (e.g. `ARC_CENTER.y = 430`, radius 590 gives about 1020), then re-check the screenshots.

### IN-02: `ScoreStore.load()` drops sections past 256 and the next save erases them

**File:** `src/core/score_store.gd:60-64, 117-134`
**Issue:** `count` counts every section (including non-`chart:` ones) and breaks at 256. Entries beyond that are never loaded, but `save()` rewrites the whole file from `_entries`, permanently discarding them. Unlikely with the hand chart, but Phase 2 imports make it reachable.
**Fix:** Count only `chart:` sections, and when the cap is hit set a flag so `save()` merges instead of overwriting.

### IN-03: "Reduce screen shake" label no longer matches what reduce-motion does

**File:** `src/ui/settings_screen.gd:161-162`
**Issue:** `Settings.reduce_motion` now also disables the glitch, the pulse, the cable pulses, the receptor pulse, the popup rise, the lens animation and slows the wall scroll. The toggle is labelled "Reduce screen shake".
**Fix:** Rename it to "Reduce motion" and add a hint line like the Low effects one.

### IN-04: Orphaned doc comment and duplicate helpers

**File:** `src/ui/palette.gd:39-48` and `src/ui/hud.gd:133-139`
**Issue:** The "c with its alpha replaced." comment sits above `fmt_depth` instead of `alpha`. `Hud.depth_text` duplicates `Palette.fmt_depth`.
**Fix:** Move the comment, and have `Hud.depth_text` call `Palette.fmt_depth(int(meters))`.

### IN-05: Intro magic numbers and hint inconsistency

**File:** `src/ui/goggles_intro.gd:396-402, 147`
**Issue:**
- `2.15` is hard-coded for the LINK ESTABLISHED text fade and duplicates the timeline.
- In QUICK mode `_hint_visible` returns false, but Space (`fire`) still skips and silently turns the 1-beat lead-in into a 3-beat one.

**Fix:** Add `LINK_TEXT_END` to `IntroTimeline`. Ignore skip when `mode == QUICK`.

### IN-06: Stale node references after teardown; unreachable code in dist.ps1

**File:** `src/ui/gameplay.gd:208-222` and `tools/dist.ps1:19-21, 26`
**Issue:**
- `_teardown` nulls `conductor`, `lane_input`, `pause_menu` and `debug_overlay` but not `arena`, `highway`, `hud`, `feedback`, `streak_counter`. After an audio-error restart these point at freed nodes. The new `_arena_miss` uses `is_instance_valid`, but other users of those refs do not.
- In `dist.ps1`, with `$ErrorActionPreference = "Stop"`, `Write-Error` throws, so the following `exit 1` lines are unreachable.

**Fix:** Null the refs in `_teardown`. Drop the dead `exit 1` or use `Write-Host` plus `exit 1`.

### IN-07: Highway cables and ring still pulse on the idle clock during the pre-count

**File:** `src/ui/highway.gd:147-151`
**Issue:** WR-03 gated the notes and the arena pulse. `BeatClock.phase(st, ...)` still feeds `_draw_cables` and `_draw_ring` with song_time 0 before the lead-in, so the cable and ring pulses sit at one fixed phase and then start beating at the count. This is cosmetic (already noted in the fix report) and does not affect timing.
**Fix:** Pass a time-based or zero-pulse phase to `_draw_cables` and `_draw_ring` while `not notes_enabled`.

### IN-08: Notes gating and beat flags are public mutable fields set from Gameplay in two places

**File:** `src/ui/gameplay.gd:115-116, 168-169`
**Issue:** `notes_enabled` and `beat_live` default to true so standalone use works, and Gameplay must remember to flip both false at build and true at the count. A future code path that builds a run without going through `_begin_count_in` (for example a spectator or periscope panel) would silently leave the board blank. This is a small coupling risk, not a current bug.
**Fix:** Wrap the two flags in one `Gameplay._set_board_live(bool)` helper so both are always set together.
