# Phase 1.2: Code Review Report

**Reviewed:** 2026-10-08
**Depth:** standard (also read src/core/conductor.gd, clock_model.gd, src/autoload/settings.gd, src/core/score_store.gd for cross-reference)
**Files Reviewed:** 14
**Status:** issues_found

## Summary

The conductor/judging gating is sound. `Conductor.begin` is only called from `Gameplay._begin_count_in`. `_process` returns until `_began`, and `lane_input.enabled` starts false. Skip, quick, F4, Retry and restart all go through `start()`, which tears down the old run root. Signal connections die with the freed nodes, so I found no stale-callback path. The Trench projection is safe: `d` is clamped before use, there is no division by zero, and a note at its judge time lands exactly on `HIT_Y`. Settings and score file handling is type-checked and clamped.

The real defects are in the intro presentation and in a few edge paths:

- The QUICK intro draws the opaque lens mask.
- The lens mask is built synchronously in GDScript.
- The board is drawn against an idle clock (song_time = 0) during the pre-count.
- Missed or early-released sustains emit degenerate polygons.

I did not run Godot, as instructed, so the engine-behaviour claims below (marked "verify") are from source reading only.

## Critical Issues

### CR-01: QUICK intro (Retry / F4 / Restart) draws the full-opacity lens mask over the arena

**File:** `src/ui/goggles_intro.gd:266-267` (with `src/core/intro_timeline.gd:124-126`)
**Issue:** `_draw_pre` calls `_draw_lens_mask(1.0, IntroTimeline.lens_open(t, mode, rm), rm)` for every ARENA phase. QUICK mode also has an ARENA phase (0.40-0.60 s). But `lens_open()` returns 0.0 for any mode other than FULL. So close = 1, open = 0 gives scale 1 and alpha 1. A fully opaque two-lens mask with a dark bridge is drawn over the arena for 0.2 s, then vanishes abruptly when COUNT starts. D-11 specifies the quick intro as "CRT blink plus a single count", with no lens. The same call is also the first `_ensure_mask()` in QUICK mode, so the mask-generation hitch (WR-02) is paid on every retry too.
**Fix:**
```gdscript
IntroTimeline.Phase.ARENA:
	if mode == IntroTimeline.Mode.FULL:
		_draw_lens_mask(1.0, IntroTimeline.lens_open(t, mode, rm), rm)
```

## Warnings

### WR-01: Degenerate ribbon quads for missed / early-released sustains (per-frame engine errors)

**File:** `src/ui/highway.gd:254-283`
**Issue:** For states other than HOLDING, `d0 = d_head`, which can be far below `D_MIN` (-0.15) once the head has passed. `Trench.point` clamps each sample. When two consecutive ribbon samples both have d < -0.15, `_edge_l[k] == _edge_l[k+1]` and `_edge_r[k] == _edge_r[k+1]`. The resulting `_quad` is a zero-area, collinear polygon. `draw_colored_polygon` should then fail triangulation ("Invalid polygon data") every frame. With a long missed sustain this starts about 0.15 * approach seconds after the head passes and lasts until the tail clears, with up to 4-9 bad quads per sustain per frame. Verify in the Godot output console.
**Fix:** Clamp the ribbon start to the drawable range before sampling, and skip empty ribbons:
```gdscript
var d0 := maxf(d_head, Trench.D_MIN) if state != S_HOLDING else maxf(d_head, 0.0)
var d1 := minf(d_tail, Trench.D_FAR)
if d1 <= d0 + 0.001:
	return
```

### WR-02: Lens mask is generated pixel-by-pixel in GDScript on the first draw, per instance, and the intro clock is already running

**File:** `src/ui/goggles_intro.gd:341-358, 76, 94-96`
**Issue:** `_ensure_mask()` loops over 480x270 = 129,600 pixels. Each iteration does two `distance_to`, three `smoothstep`, several `min/max`, a `Color` allocation and a `set_pixel`. That is a synchronous GDScript hitch, likely hundreds of ms, inside the first `_draw()`. `_mask_tex` is an instance variable, so it is rebuilt on every dive. `_origin_usec` is set in `setup()`, before the stall. The wall-clock `_elapsed()` therefore jumps ahead by the hitch length. The 0.6 s lens-close animation is partly or wholly skipped, and the "A TO SKIP" hint timing is off.
**Fix:** Make the texture a `static var` built once (like `_room_glow_tex`). Prefer a cheap construction, either a shader or a `GradientTexture2D`, or build it once at boot (menu `_ready`) or on a thread. At minimum, reset the clock after the first draw:
```gdscript
# in _process, first PRE frame:
if not _clock_started:
	_clock_started = true
	_origin_usec = Time.get_ticks_usec()
```

### WR-03: Board and arena are drawn against an idle clock (song_time == 0) during the whole pre-count

**File:** `src/ui/highway.gd:141`, `src/ui/arena.gd:194`, `src/core/clock_model.gd:79-80`
**Issue:** Until `Conductor.begin`, `ClockModel` is IDLE and `song_time()` returns 0.0. During the 0.6-2.6 s pre-count:
- Highway draws notes with `d = note_time / approach`. Any note inside the first `approach` seconds (1.5 s at 1x) is visible on the cables, and a note at t = 0 sits on the ring.
- When `_begin_count_in` starts the lead-in, song_time jumps to -lead_in and those notes pop out of view and reappear far away.
- Arena `_pulse` is `BeatClock.pulse(phase(0))` = 1.0, constant. The glow and walls stay at maximum pulse and then start beating at the count.

The timing core is unaffected, but the reveal is visibly wrong for charts with early notes.
**Fix:** Do not draw notes (or drive the beat) until `Gameplay.is_began()`. For example, add `var notes_enabled := false` to Highway, set it in `_begin_count_in`, and guard `_draw_notes`. In Arena, use `_t`-based phase while `not _conductor.is_active_or_began()`.

### WR-04: Esc during the pre-count skips the intro instead of staying pause/back

**File:** `src/ui/goggles_intro.gd:140`
**Issue:** D-11 says "Space skips ... Esc stays pause/back". `_unhandled_input` treats the `pause` action as skip as well. The event is marked handled, and `Gameplay._unhandled_input` also requires `_began` before pausing, so Esc can neither pause nor leave during the 2.6 s intro. A first Esc just skips, and a second is needed to pause. The README and hint only advertise Space and A.
**Fix:** Skip on `fire` only (plus pad A, which is mapped to `fire`). Optionally open the pause menu on `pause` once supported, or leave it unhandled.

### WR-05: Miss reduces arena energy twice per miss (x0.16 instead of x0.4)

**File:** `src/ui/gameplay.gd:105-106, 179-187` and `src/ui/arena.gd:163-166`
**Issue:** A MISS fires `judge.judged` (handled by `_on_judged_arena`) and then `score.hull_changed` with delta < 0 (handled by `_on_hull_arena`). Both call `arena.on_miss()`, which multiplies `_energy` by 0.4 and re-arms the glitch. Net effect: energy x0.16 on every miss, plus a double trigger. Stray-press hull damage hits `on_miss` too.
**Fix:** Drive it from one source. Keep only `_on_hull_arena`, or only `_on_judged_arena`. If both are wanted, guard `on_miss` with a short debounce.

### WR-06: Lead-in length is not bounded against output latency or very slow tempos

**File:** `src/ui/gameplay.gd:156-160` and `src/core/conductor.gd:59-68`
**Issue:** Lead-in is `beats * 60/bpm`. With QUICK (1 beat) at high BPM (e.g. 240 bpm gives 0.25 s) and a nonzero output latency or `audio_offset` (Bluetooth, WASAPI shared mode), `Conductor._start` computes `_play_at = -(mix_delay + latency) - audio_offset`. If that is <= `song_time()` (= -lead_in), it starts audio immediately, so the music is heard late relative to song_time 0. The clock then runs at half rate to resync. At very low BPM (30-40) a 3-beat count-in lasts 4.5-6 s. Both are edge cases for charts, but real imports arrive in Phase 2.
**Fix:** Bound the lead-in, for example `lead = clampf(beats * spb, 0.8, 4.0)`. Keep the numeral timing derived from `lead / beats` (`_spb`) in both Gameplay and GogglesIntro.

## Info

### IN-01: Hull arc dips into the outer 32 px bottom margin

**File:** `src/ui/hud.gd:13-14, 221`
**Issue:** With `ARC_CENTER=(960,450)`, `ARC_RADIUS=612` and angles 1.114-2.028 rad, the arc's lowest point (~pi/2) is at y = 1062. That is inside the bottom 32 px (>= 1048), which contradicts the class doc "Nothing persistent in the outer 32 px" and D-06 clean edges.
**Fix:** Lower the radius or move the centre up (e.g. `ARC_CENTER.y = 430`, radius 590 gives about 1020), then re-check the screenshots.

### IN-02: `ScoreStore.load()` drops sections past 256 and the next save erases them

**File:** `src/core/score_store.gd:60-64, 117-134`
**Issue:** `count` counts every section (including non-`chart:` ones) and breaks at 256. Entries beyond that are never loaded, but `save()` rewrites the whole file from `_entries`, permanently discarding them. Unlikely with the hand chart, but Phase 2 imports make it reachable.
**Fix:** Count only `chart:` sections, and when the cap is hit set a flag so `save()` merges instead of overwriting.

### IN-03: "Reduce screen shake" label no longer matches what reduce-motion does

**File:** `src/ui/settings_screen.gd:161-162`
**Issue:** `Settings.reduce_motion` now also disables the glitch, the pulse, the cable pulses, the receptor pulse, the popup rise, the lens animation and slows the wall scroll. The toggle is labelled "Reduce screen shake".
**Fix:** Rename it to "Reduce motion" and add a hint line like the Low effects one.

### IN-04: Orphaned doc comment and duplicate helpers

**File:** `src/ui/palette.gd:39-40, 41-48` and `src/ui/hud.gd:133-139`
**Issue:** The "c with its alpha replaced." comment sits above `fmt_depth` instead of `alpha`. `Hud.depth_text` duplicates `Palette.fmt_depth`.
**Fix:** Move the comment, and have `Hud.depth_text` call `Palette.fmt_depth(int(meters))`.

### IN-05: Intro magic numbers and hint inconsistency

**File:** `src/ui/goggles_intro.gd:396-402, 140`
**Issue:**
- `2.15` is hard-coded for the LINK ESTABLISHED text fade and duplicates the timeline.
- In QUICK mode `_hint_visible` returns false, but Space still skips and silently turns the 1-beat lead-in into a 3-beat one.

**Fix:** Add `LINK_TEXT_END` to `IntroTimeline`. Ignore skip when `mode == QUICK`.

### IN-06: Stale node references after teardown; unreachable code in dist.ps1

**File:** `src/ui/gameplay.gd:189-204` and `tools/dist.ps1:19-21, 26`
**Issue:**
- `_teardown` nulls `conductor`, `lane_input`, `pause_menu` and `debug_overlay` but not `arena`, `highway`, `hud`, `feedback`, `streak_counter`. After an audio-error restart these point at freed nodes, and the `arena != null` guards (lines 180, 185, 276) pass for freed instances.
- In `dist.ps1`, with `$ErrorActionPreference = "Stop"`, `Write-Error` throws, so the following `exit 1` lines are unreachable. The exit code is still non-zero, but the intent is misleading.

**Fix:** Null the refs in `_teardown` (or use `is_instance_valid`). Drop the dead `exit 1` or use `Write-Host` plus `exit 1`.
